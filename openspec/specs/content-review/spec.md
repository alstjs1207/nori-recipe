# 콘텐츠·재료·이미지·사용자 검수

## Purpose

현재 코드·테스트와 기존 제품 정책을 대조한 계약이다. 검증 공백은 `openspec/known-gaps.md`, 완료 근거는 `openspec/completed-work.md`를 참고한다.

## Requirements

### Requirement: CON-001 마스터와 게시 안전 검증

콘텐츠 MUST 0~48개월·7개 발달영역·표준 slug·개별 출처와 유효 상태를 사용하고 substitutes 배열은 비워 둔다. live에는 reviewPending 재료, 생밀가루·생반죽 직접 놀이, 36개월 미만의 작은 구슬·비즈·폼폼·워터비즈·플레이콘·일반 슬라임을 허용하지 않는다. 이 목록은 코드의 게시 규칙이며 외부 안전 기준 전체를 대신하지 않는다.

#### Scenario: 검증 실패

- **WHEN** 미승인 재료 또는 금지 게시 조건이 있다
- **THEN** 게시 콘텐츠 검증에서 오류를 반환한다.

#### Scenario: 이력 보존

- **WHEN** 제외 놀이가 archived 상태로 남아 있다
- **THEN** 게시 금지를 유지하면서 이력은 보존할 수 있다.

### Requirement: CON-002 초안부터 이미지 준비까지

수집 파이프라인 SHALL 원문→정규화→실제 ID의 draft→놀이 및 없는 새 재료의 실제 이미지 생성·저장→배치→검수 링크 순으로 준비한다. 신규 배치는 현재 내용 해시와 실제 이미지·생성 기록이 모두 준비된 경우에만 만든다. 누락·stale·손상은 초안과 완료 결과를 보존하며 부분 배치나 사용자 승인으로 꾸미지 않는다.

#### Scenario: 이미지 미완료

- **WHEN** 신규 수집 놀이의 이미지가 하나라도 미완료다
- **THEN** 신규 배치를 만들지 않는다.

#### Scenario: 재개

- **WHEN** 완료한 이미지와 같은 정규화 파일·ID가 있다
- **THEN** 준비 결과를 재사용하고 미완료만 이어서 처리한다.

### Requirement: CON-003 현재 내용에 대한 명시적 승인

게시 도구 MUST 사용자 승인된 항목만 현재 내용·재료 정의·이미지 해시·확인란과 함께 검증한 뒤 백업·반영한다. 내용이나 이미지 변경은 과거 승인을 무효화한다. 재료는 신규 추가·기존 대체·보류를 따로 결정하며 재료 승인만으로 놀이가 게시되지 않는다. JSON 가져오기·생성 완료·서버 시작은 승인이 아니다.

#### Scenario: 오래된 승인

- **WHEN** 이미지 또는 내용이 승인 이후 변경된다
- **THEN** 기존 승인을 거부하고 재검수를 요구한다.

#### Scenario: 사용자 승인

- **WHEN** 현재 놀이·재료·이미지 확인과 승인된 한 항목을 반영한다
- **THEN** 검증·백업 후 해당 항목만 live 및 이미지 매핑에 반영한다.

### Requirement: CON-004 놀이 이미지의 비공개 원본과 공개 서비스 자산

로컬 이관 도구 MUST 원본과 서비스용 파생 자산의 버킷·객체 경로를 구분하고, 기준 커밋의 승인된 live 상태·내용 해시·원본 바이트와 일치한 이미지의 검증 완료 파생 자산만 공개 후보에 포함한다. draft·archived·review는 원본만 보관할 수 있다. 공개 후보와 오류 보고에는 비공개 원본 경로·서명 URL·관리자 자격 증명을 넣지 않는다. 실제 전체 원본224개·승인 live208개의 파생416개를 전송/다운로드 검증했다. 웹·공유/PWA와 Preview/Production 배포를 완료했으며 네이티브는 제외한다.

#### Scenario: 초안과 검토 중 이미지

- **WHEN** draft·archived·review 또는 기존 승인 해시와 다른 이미지의 이관을 실행한다
- **THEN** 해당 파생 이미지의 신규 공개 게시를 차단하며 놀이 상태나 승인 결과를 변경하지 않는다.

#### Scenario: 관리 경계

- **WHEN** 관리 도구를 기본 옵션 또는 디렉터리 fixture 모드로 실행한다
- **THEN** 기본 dry-run은 객체와 파일을 쓰지 않고 환경변수만으로 원격 접속을 활성화하지 않으며, 공개 후보에 원본 접근 정보와 자격 증명을 포함하지 않는다.

#### Scenario: 원본에 대한 비인가 접근

- **WHEN** 관리자 권한 없는 요청이 비공개 원본을 조회하거나 이미지를 쓰기·삭제하려 한다
- **THEN** 허용하지 않고 원본 공개나 관리자 자격 증명 전달로 대체하지 않는다. 실제 접근 결과는 ID별 이관 보고서에 구분한다.

#### Scenario: 승인된 서비스 이미지 조회

- **WHEN** 웹 방문자나 공유 크롤러가 승인된 live 놀이의 이미지와 정적 공유 HTML을 요청한다
- **THEN** 만료 서명 URL·관리자 키·로그인 없이 공개 파생 자산을 제공하고 웹과 OG는 같은 승인 버전의 상세 URL을 사용한다.

### Requirement: CON-005 놀이 이미지 이관의 무결성과 검수 호환성

로컬 이관 도구 SHALL ID별 원본·상세·썸네일의 전체 SHA-256·바이트 수·불변 버전 경로를 기록하고 다운로드한 객체를 검증한다. 부분 성공은 체크포인트와 객체로 보존하고 재실행 시 실제 객체를 다시 검증한다. 복원은 검증 후 없는 파일만 생성하며 다른 바이트를 덮어쓰지 않는다. 원본과 기존 검수 해시·사용자 데이터를 변경하지 않으며, 비공개 전환된 공개 후보와 부분 공개 객체는 정리 후보로 기록한다. 전체 Storage 업로드를 검증했고 사용자 요청으로 검증된 원본224개의 Git 추적만 제외하며 로컬 바이트·다른 이미지·과거 이력은 유지한다. 관리 복원 통합·실제 롤백 검증은 별도 후속이다. 네이티브는 후속 사용자 요청으로 제외한다.

#### Scenario: 기존 승인 이미지의 위치만 변경

- **WHEN** 기존 승인 바이트를 전송한 뒤 다운로드 검증하고 누락된 로컬 원본을 복원한다
- **THEN** 원본과 검수 이미지 해시를 유지하며 위치 변경만으로 재승인을 요구하지 않는다.

#### Scenario: 누락 또는 부분 업로드

- **WHEN** 객체 전송·다운로드·해시 검증이 실패하거나 같은 경로에 다른 바이트가 있다
- **THEN** 실패한 ID의 새 공개 후보를 활성화하지 않고 원본·완료 객체·기존 정상 참조를 보존하며, 재실행에서 체크포인트만 신뢰해 검증을 생략하지 않는다.

#### Scenario: 승인 이후 이미지 변경

- **WHEN** 내용 또는 원본 바이트가 기준 승인 이후 변경된다
- **THEN** 공개 게시를 거부하고 재검수를 요구하며 기존 승인과 로컬 파일을 임의 변경하지 않는다.

#### Scenario: 콘텐츠 비공개 전환

- **WHEN** 기존 공개 후보 또는 전송 중인 이미지가 draft·archived·review 상태가 된다
- **THEN** 공개 후보에서 제외하고 기존 공개 객체·부분 전송 객체를 정리 후보에 포함하되 원격 삭제는 실행하지 않는다.

2026-11-15 실제 3개 파일럿의 설정·해시·복원·접근 제어 근거는 [실행 보고서](../../changes/migrate-play-images-to-supabase-storage/evidence/storage-pilot-2026-11-15.md)를 따른다. 해당 결과는 전체 이미지 이관·네이티브·배포 완료를 의미하지 않는다.

2026-11-15 전체 Storage 전송·익명 공개/원본 차단·다운로드 해시·ID별 결과와 원본 보존은 [전체 실행 보고서](../../changes/migrate-play-images-to-supabase-storage/evidence/full-upload-2026-11-15.md)를 따른다. 실제 소비 경로/배포/네이티브 전환 완료와 구분한다.

2026-11-15 최종 웹 이관 완료와 사용자 공유 확인은 [검증 기록](../../changes/migrate-play-images-to-supabase-storage/verification.md)을 따른다. 수동 복원 도구와 아직 미구현인 관리 UI 자동 복원·실제 전체 복원/롤백·서비스 내 제공처 고지는 [후속 목록](../../follow-ups/play-image-operations.md)에서 구분한다.

### Requirement: CON-006 재료 이미지 원본 보존과 승인 파생 이관

재료 이관 도구 MUST 기존 재료 정의·매핑·원본 바이트의 고정 기준과 일치하는 승인 이미지 파생만 공개한다. 미사용·검수 대기 원본은 비공개로 보존하며 브랜드 기본 이미지를 공개 승인으로 간주하지 않는다. 원본/내용 SHA-256·크기·불변 버전을 검증하고 기존 객체를 덮어쓰지 않으며 부분 진행을 재검증해 재개한다. 관리자 키·원본 접근 정보는 앱·Git·CI/Vercel·공개 매니페스트에서 제외한다. 로컬 원본·검수 해시·사용자 데이터를 보존한다.

#### Scenario: 승인된 재료와 미사용 원본

- **WHEN** 기존 커밋과 동일한 재료 정의·실제 매핑·원본을 이관한다
- **THEN** 승인된 매핑만 공개 WebP 후보로 만들고 미사용 원본은 비공개만 보관한다. 검수 대기·브랜드 기본 그림은 공개 재료 파생에서 제외한다.

#### Scenario: 변경과 부분 실패

- **WHEN** 정의·매핑·원본이 바뀌거나 전송·다운로드·해시 검증이 실패한다
- **THEN** 해당 신규 후보를 활성화하지 않고 원본·완료 객체·체크포인트를 유지한다. 재실행은 실제 객체를 다시 검증하며 동일 경로의 다른 바이트는 거부한다.

#### Scenario: 원본 복원과 Git 제외

- **WHEN** 검증한 비공개 원본을 복원하거나 Git 추적에서 제외한다
- **THEN** 다운로드 해시·JPEG를 검증하고 없는 파일만 생성한다. 충돌 파일은 덮어쓰지 않는다. 원격 보존·원본 없는 빌드 검증 후에만 검증 대상의 Git 추적을 제외하며 로컬 바이트·다른 이미지·과거 이력은 보존한다.

#### Scenario: 관리 접근과 기본 실행

- **WHEN** 기본 dry-run·디렉터리 fixture 또는 익명 요청을 실행한다
- **THEN** dry-run은 IO 쓰기·원격 전송을 하지 않고 fixture는 관리자 키를 읽지 않는다. 익명 원본 읽기·쓰기·삭제는 차단되며 공개 파생은 키·로그인·서명 URL 없이 읽을 수 있다.

### Requirement: CON-007 승인 이미지의 최종 등록 파이프라인

최종 등록 도구 MUST 기존 사용자 승인·현재 내용/이미지 검증을 통과한 놀이와 신규 추가 재료만 Supabase 비공개 JPEG 원본·공개 WebP로 전송한다. 기존 이관과 같은 불변 경로·변환을 사용하고 다운로드 SHA-256·크기와 인증 없는 공개 읽기를 검증한 뒤 등록 상태·공개 등록 매니페스트·재료 소스 해시를 함께 반영한다. 키는 로컬 관리자 프로세스에만 제공하고 공급자 오류 본문은 반환하지 않는다. 생성·검수 준비·조회·저장·JSON 가져오기·dry-run은 업로드하지 않는다.

#### Scenario: 신규 승인 등록

- **WHEN** 사용자가 현재 놀이 또는 신규 재료를 승인한다
- **THEN** 해당 원본·파생 전송과 다운로드/공개 읽기 검증 후에만 등록한다. 재료 승인만으로 놀이는 live가 되지 않는다.

#### Scenario: 부분 실패와 재시도

- **WHEN** 키 누락·업로드·다운로드·익명 읽기·해시 검증이 실패한다
- **THEN** 로컬 등록 상태·공개 매니페스트를 바꾸지 않고 초안·원본·완료 객체를 보존한다. 재시도는 기존 객체를 재검증하며 없는 경로만 생성하고 다른 바이트를 덮어쓰지 않는다.

#### Scenario: 공개 빌드 연결

- **WHEN** 새 승인 이미지가 포함된 공개 빌드를 실행한다
- **THEN** 기존 이관 기록에 별도의 공개 등록 매니페스트를 병합하고 새 승인 버전을 우선하며 기존 내용/매핑·공개 바이트 검증과 비공개 필터를 유지한다. 관리자 키·원본 복원·배포 설정 변경은 필요하지 않다.
