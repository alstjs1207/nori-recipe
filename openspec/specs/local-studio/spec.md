# 로컬 스튜디오·복구·추천 실험실

## Purpose

현재 코드·테스트와 기존 제품 정책을 대조한 계약이다. 검증 공백은 `openspec/known-gaps.md`, 완료 근거는 `openspec/completed-work.md`를 참고한다.

## Requirements

### Requirement: STU-001 루프백과 쓰기 요청 검증

로컬 서버 MUST 루프백에서 카탈로그·재료·배치와 허용된 자산만 제공하고 임의 파일·심볼릭 링크·경로 이탈을 거부한다. 쓰기에는 동일 origin, 세션 토큰, JSON·2MiB 제한, 현재 revision·항목·해시를 검증한다. 오래된 화면은 409, 복구 필요 거래는 423으로 차단한다.

#### Scenario: 오래된 화면

- **WHEN** 외부 파일 변경 후 이전 revision으로 승인한다
- **THEN** 409로 거부한다.

#### Scenario: 임의 파일

- **WHEN** 허용 경로 밖 파일을 요청한다
- **THEN** 내용을 공개하지 않는다.

### Requirement: STU-002 사용안함 처리와 거래 복구

스튜디오 MUST 사용자가 사용안함으로 선택한 놀이 한 개를 마스터·배치 연결·검수 상태·대표 이미지·앱 매핑에서 제거하며 공용 재료·수집 원본·이전 백업을 유지한다. 쓰기 전 거래 백업을 만들고 미완료 거래는 추가 쓰기를 차단한 뒤 문서화한 복구 절차를 사용한다.

#### Scenario: 사용안함

- **WHEN** 현재 화면에서 놀이 한 개를 사용안함 처리한다
- **THEN** 연관 표시를 제거하고 백업 및 빈 배치 URL을 보존한다.

### Requirement: STU-003 명시적 Codex 요청과 중복 방지

스튜디오 SHALL 사용자가 Codex 검수 요청 버튼을 누를 때 의견을 먼저 저장하고 현재 수집 건 전체를 새 로컬 채팅으로 전달한다. 동일 내용·의견 요청은 기존 영수증을 재사용하며 전달 여부가 불명확하면 중복 생성을 막는다. 요청은 수정 검토 범위이며 자동 승인·커밋·배포 권한이 아니다.

#### Scenario: 반복 요청

- **WHEN** 같은 수집 건의 동일 내용·의견을 다시 요청한다
- **THEN** 기존 채팅 링크를 재사용한다.

#### Scenario: 조회만

- **WHEN** 배치 GET이나 서버 시작만 실행한다
- **THEN** 새 채팅을 만들지 않는다.

### Requirement: STU-004 읽기 전용 추천 실험실

스튜디오 SHALL /recommendations에서 실제 recommend 엔진을 현재 마스터로 실행하며 조건·근거와 월령별 결과를 보여 준다. 실험실은 홈 고정 세트·콘텐츠·승인을 바꾸지 않고 개인 피드백을 불러오지 않으며 기본 개인화 점수는 50을 사용한다.

#### Scenario: 조건 시뮬레이션

- **WHEN** 월령·재료·준비 확인 조건을 바꾼다
- **THEN** 실제 엔진 결과를 관찰하고 마스터·홈 저장값은 변경하지 않는다.

### Requirement: STU-005 승인 전송과 로컬 거래의 일관성

스튜디오와 승인 CLI MUST 같은 이미지 등록 모듈을 사용한다. 스튜디오는 선택한 한 항목만, CLI는 승인 결과의 해당 종류만 처리한다. 전송 후 현재 파일 revision을 다시 대조해 외부 변경은 보존하고 오래된 반영은 거부한다. 등록 상태·공개 매니페스트·재료 소스 해시는 같은 복구 가능한 거래에 포함한다. 전송 실패는 원격 응답/키를 노출하지 않는 오류로 알리고 사용자가 설정·연결을 보완해 재시도할 수 있게 한다.

#### Scenario: 전송 중 외부 변경

- **WHEN** 업로드를 기다리는 동안 본문·이미지·매핑·공개 등록 기록이 외부에서 바뀐다
- **THEN** 최종 반영은 409로 거부하고 외부 수정과 로컬 초안을 유지한다.

#### Scenario: 중단된 등록 복구

- **WHEN** 로컬 등록 거래가 일부 파일 반영 후 중단된다
- **THEN** 기존 복구 절차로 등록 상태·공개 매니페스트·재료 소스 해시를 이전 바이트로 함께 복구하고 외부 수정은 덮어쓰지 않는다.

### Requirement: STU-006 신규 놀이 사용 가이드

스튜디오 SHALL 모든 서버 화면의 공유 메뉴에서 `/guide` 사용 가이드를 제공한다. 가이드는 수집 요청·초안/이미지 준비·새 재료 선행 검수·놀이 승인 후 Supabase 업로드/검증·Preview 확인과 운영 반영 절차 및 수정/실패 재개 방법을 안내한다. 일회성 키 설정은 가이드에 포함하지 않는다. 조회는 콘텐츠·검수 상태를 변경하거나 자동 등록/배포하지 않으며 기존 데스크톱/모바일 스튜디오 메뉴와 읽기 전용 경계를 유지한다.

#### Scenario: 사용 가이드 열기

- **WHEN** 사용자가 스튜디오 메뉴의 사용 가이드를 선택한다
- **THEN** 현재 메뉴를 표시한 등록 절차와 검수·라이브러리 바로가기를 제공하며 키 설정은 표시하지 않는다.

#### Scenario: 읽기 전용과 정적 검수

- **WHEN** 사용 가이드를 GET/HEAD로 조회하거나 file:// 검수 화면을 생성한다
- **THEN** 마스터·검수 기록·이미지를 변경하지 않고 정적 검수에 서버 전용 가이드 링크를 추가하지 않는다.
