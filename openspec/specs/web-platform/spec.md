# 웹·PWA·공유·배포

## Purpose

현재 코드·테스트와 기존 제품 정책을 대조한 계약이다. 검증 공백은 `openspec/known-gaps.md`, 완료 근거는 `openspec/completed-work.md`를 참고한다.

## Requirements

### Requirement: WEB-001 공개 상세·공유 메타데이터·origin

웹 빌드 SHALL live 놀이마다 직접 링크와 공유 메타데이터를 생성하며 사이트 대표 이미지와 버전된 놀이 이미지를 사용한다. 운영 기준 주소는 https://www.nori-recipe.com이며 Preview는 해당 VERCEL_URL을 사용한다. 직접 상세는 온보딩 없이 열리며 존재하지 않는 자산·놀이 경로는 404를 반환한다.

#### Scenario: 직접 링크

- **WHEN** 처음 방문한 사용자가 /play/play_001을 연다
- **THEN** 온보딩 없이 해당 공개 상세를 본다.

#### Scenario: 미리보기

- **WHEN** Preview 빌드에 VERCEL_URL이 있다
- **THEN** 해당 주소로 메타데이터를 만든다.

### Requirement: WEB-002 설정의 설치·오프라인·선택 업데이트

PWA SHALL 설정의 앱처럼 이용하기에서 설치 또는 수동 안내를 제공하고 설치 후 상태를 표시한다. 버전별 앱 셸·방문 이미지 캐시를 사용하고 이미지 캐시는 최대 80개로 제한한다. 새 버전은 사용자의 새 버전 열기 선택으로 적용하며 모든 미방문 화면·이미지의 오프라인 제공을 보장하지 않는다. 설치된 웹 앱은 standalone 모드와 운영체제가 제공한 viewport를 사용하고 상하좌우 안전 영역에 조작부가 가려지지 않아야 한다. 첫 방문·설정·일반 화면의 하단 메뉴는 공통 셸에서 한 번만 표시하고 메뉴가 있을 때 하단 안전 여백은 메뉴에서만 적용한다. 상세·피드백에서는 메뉴를 숨긴다. iPhone 수동 안내는 웹 앱으로 열기 선택을 포함한다.

#### Scenario: 오프라인

- **WHEN** 이미 방문한 앱을 오프라인으로 연다
- **THEN** 캐시된 셸·미디어를 사용한다.

#### Scenario: 업데이트

- **WHEN** 새 서비스 워커가 대기한다
- **THEN** 사용자 동작 후 SKIP_WAITING으로 적용한다.

#### Scenario: 설치 화면 영역

- **WHEN** iPhone 홈 화면에서 독립 웹 앱으로 연다
- **THEN** 앱 배경이 화면을 채우며 헤더·하단 메뉴·상세 하단 버튼은 안전 영역 안에 표시된다.

#### Scenario: 브라우저 바로가기

- **WHEN** 브라우저 모드에서 설치 안내를 연다
- **THEN** Safari 공유 메뉴·홈 화면에 추가·웹 앱으로 열기 및 홈 화면 실행을 안내하며 저장소를 삭제하도록 요구하지 않는다.

#### Scenario: 첫 방문 하단 메뉴

- **WHEN** 아이 정보가 없는 상태로 첫 실행하거나 /start를 연다
- **THEN** 모바일 첫 방문 화면에도 발견·탐색·저장·기록 메뉴가 표시되며 프로필을 강제로 저장하지 않고 탐색할 수 있다.

#### Scenario: 공통 메뉴와 하단 여백

- **WHEN** 첫 방문·설정·발견·탐색을 오가거나 화면 크기가 바뀐다
- **THEN** 하단 메뉴는 한 번만 표시되고 앱 viewport 하단에 맞춰지며 콘텐츠와 메뉴에서 안전 여백을 중복 적용하지 않는다. 상세·피드백에서는 메뉴 없이 콘텐츠의 안전 여백을 유지한다.

### Requirement: WEB-003 에셋 준비와 브랜치 배포 경계

빌드 SHALL 원본 JPEG를 보존하고 웹 WebP·썸네일·재료·아이콘·내용 해시 CSS를 생성한다. 개발은 preview→Vercel Preview, 확인한 preview의 main 병합은 Production으로 구분한다. PUBLIC_ORIGIN 운영 값은 Production에만 설정한다. 로컬 검증 명령은 커밋·푸시·공개 배포를 수행하지 않는다.

#### Scenario: 에셋 교체

- **WHEN** 같은 재료 또는 환영 그림을 바꿔 빌드한다
- **THEN** 내용 해시 주소를 갱신해 이전 캐시와 구분한다.

#### Scenario: 검증 실행

- **WHEN** verify:local을 실행한다
- **THEN** 로컬 테스트·빌드까지만 실행한다.

### Requirement: WEB-004 정적 서비스 소개 페이지

웹 빌드 SHALL 앱 경로와 분리된 정적 서비스 소개 페이지 `/intro`를 생성한다. 페이지의 놀이·재료·월령·발달영역 수치는 빌드 시점의 live 놀이와 검수 대기를 제외한 재료 레지스트리에서 계산하며 하드코딩하지 않는다. 화면 이미지는 실제 서비스 웹 화면 캡처를 내용 해시 WebP로 제공한다. 브랜드명은 ‘노리 레시피’로 표기하고, 동작 효과(숫자 세어 올리기·막대 채우기·스크롤 등장·데모 결과 전환)는 동작 줄이기 미설정과 스크립트 실행 시에만 적용해 그 외에는 모든 내용과 최종 수치를 처음부터 보여 주며, 미리 찾아보기 데모는 live 놀이의 공개 상세 링크만 사용하며 검수 중 그림을 노출하지 않는다. 소개 페이지는 분석 스크립트·서비스 워커 등록·외부 폰트를 추가하지 않으며 루트와 앱 경로의 기존 동작을 바꾸지 않는다.

#### Scenario: 데이터 기반 수치

- **WHEN** live 놀이 또는 재료 레지스트리가 바뀐 뒤 웹을 빌드한다
- **THEN** `/intro`의 놀이 수·준비 5분 이내 놀이 수·재료 수·월령 범위·발달영역별 수가 새 데이터로 계산된다.

#### Scenario: 소개 페이지 제공

- **WHEN** 처음 방문한 사용자가 `/intro`를 연다
- **THEN** 앱 온보딩이나 리다이렉트 없이 소개 페이지를 보고, 시작 버튼으로 `/`에, 둘러보기로 `/search`에 이동할 수 있다.

#### Scenario: 미리 찾아보기

- **WHEN** 소개 페이지에서 월령 구간과 재료 칩을 고른다
- **THEN** 해당 월령과 겹치고 필수 재료가 모두 선택된 live 놀이 수와 최대 3개의 공개 상세 링크를 보여 준다. imageStatus=review 놀이는 기본 브랜드 이미지를 쓴다.

#### Scenario: 공유 주소

- **WHEN** Preview 또는 운영 빌드에서 소개 페이지를 생성한다
- **THEN** canonical·OG 주소가 해당 배포 origin의 `/intro`로 채워진다.

#### Scenario: 동작 줄이기와 스크립트 미실행

- **WHEN** 기기의 동작 줄이기가 켜져 있거나 자바스크립트가 꺼진 상태로 `/intro`를 연다
- **THEN** 숨겨진 섹션 없이 모든 내용이 보이고 숫자·막대는 처음부터 최종 값으로 표시된다. 동작 줄이기가 켜져 있으면 재료 띠도 멈춘다.
