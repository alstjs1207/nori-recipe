# 웹·PWA·공유·배포

## Purpose

현재 코드·테스트와 기존 제품 정책을 대조한 계약이다. 검증 공백은 `openspec/known-gaps.md`, 완료 근거는 `openspec/completed-work.md`를 참고한다.

## Requirements

### Requirement: WEB-001 공개 상세·공유 메타데이터·origin

웹 빌드 SHALL live 놀이마다 직접 링크와 공유 메타데이터를 생성하며 사이트 대표 이미지와 버전된 놀이 이미지를 사용한다. 운영 기준 주소는 https://www.nori-recipe.com이며 Preview는 해당 VERCEL_URL을 사용한다. 직접 상세는 온보딩 없이 열리며 존재하지 않는 자산·놀이 경로는 404를 반환한다.

#### Scenario: 직접 링크

- **WHEN** 처음 방문한 사용자가 /play/play_001을 연다
- **THEN** 온보딩 없이 해당 공개 상세를 본다.

#### Scenario: 미리보기

- **WHEN** Preview 빌드에 VERCEL_URL이 있다
- **THEN** 해당 주소로 메타데이터를 만든다.

### Requirement: WEB-002 설정의 설치·오프라인·선택 업데이트

PWA SHALL 설정의 앱처럼 이용하기에서 설치 또는 수동 안내를 제공하고 설치 후 상태를 표시한다. 버전별 앱 셸·방문 이미지 캐시를 사용하고 이미지 캐시는 최대 80개로 제한한다. 새 버전은 사용자의 새 버전 열기 선택으로 적용하며 모든 미방문 화면·이미지의 오프라인 제공을 보장하지 않는다. 설치된 웹 앱은 standalone 모드와 운영체제가 제공한 viewport를 사용하고 상하좌우 안전 영역에 조작부가 가려지지 않아야 한다. 첫 방문·설정·일반 화면의 하단 메뉴는 공통 셸에서 한 번만 표시하고 메뉴가 있을 때 하단 안전 여백은 메뉴에서만 적용한다. 상세·피드백에서는 메뉴를 숨긴다. iPhone 수동 안내는 웹 앱으로 열기 선택을 포함한다.

Storage 캐시는 허용 origin·공개 버킷의 익명 CORS 이미지로 제한하고 실패는 기본 표시한다.

#### Scenario: 오프라인

- **WHEN** 이미 방문한 앱을 오프라인으로 연다
- **THEN** 캐시된 셸·미디어를 사용한다.

#### Scenario: 업데이트

- **WHEN** 새 서비스 워커가 대기한다
- **THEN** 사용자 동작 후 SKIP_WAITING으로 적용한다.

#### Scenario: 설치 화면 영역

- **WHEN** iPhone 홈 화면에서 독립 웹 앱으로 연다
- **THEN** 앱 배경이 화면을 채우며 헤더·하단 메뉴·상세 하단 버튼은 안전 영역 안에 표시된다.

#### Scenario: 브라우저 바로가기

- **WHEN** 브라우저 모드에서 설치 안내를 연다
- **THEN** Safari 공유 메뉴·홈 화면에 추가·웹 앱으로 열기 및 홈 화면 실행을 안내하며 저장소를 삭제하도록 요구하지 않는다.

#### Scenario: 첫 방문 하단 메뉴

- **WHEN** 아이 정보가 없는 상태로 첫 실행하거나 /start를 연다
- **THEN** 모바일 첫 방문 화면에도 발견·탐색·저장·기록 메뉴가 표시되며 프로필을 강제로 저장하지 않고 탐색할 수 있다.

#### Scenario: 공통 메뉴와 하단 여백

- **WHEN** 첫 방문·설정·발견·탐색을 오가거나 화면 크기가 바뀐다
- **THEN** 하단 메뉴는 한 번만 표시되고 앱 viewport 하단에 맞춰지며 콘텐츠와 메뉴에서 안전 여백을 중복 적용하지 않는다. 상세·피드백에서는 메뉴 없이 콘텐츠의 안전 여백을 유지한다.

#### Scenario: Storage 캐시 허용 경계

- **WHEN** 설정한 origin·공개 버킷의 불변 버전 이미지 요청을 처리한다
- **THEN** 성공한 읽기 가능한 CORS 이미지만 캐시하고 오류·opaque·비이미지·redirect·무관한 origin·비공개/인증/서명 경로는 제외한다. 로컬/Storage 미디어 합계 80개와 선택 업데이트를 유지한다. 오프라인·경계 회귀는 fixture이며 실제 Supabase 3개 이미지의 CORS 표시·캐시 해시는 별도로 확인했다.


#### Scenario: 준비 후 첫 오프라인 기본 화면

- **WHEN** 온라인에서 앱 셸 준비를 마친 뒤 처음 오프라인으로 홈·시작·설정/안내를 연다
- **THEN** 방문 이력 없이 기본 화면과 안내를 표시한다. 전체 이미지 선저장은 요구하지 않으며 미방문 이미지는 기본 표시, 방문 미디어는80개 제한을 유지한다.

#### Scenario: 기본 화면 준비 상태

- **WHEN** 최초 셸 설치가 진행·완료·실패하거나 기존 활성 셸이 있는 상태로 재실행한다
- **THEN** 준비 중·기본 화면 준비 완료·실패를 구분하고 실패 설치를 완료로 표시하지 않는다. 기존 활성 셸은 보존하며 새 버전은 사용자 선택 후 적용한다.

### Requirement: WEB-003 에셋 준비와 브랜치 배포 경계

빌드 SHALL 놀이 원본을 로컬에 보존하고 Git에서 제외하며, 공개 모드에서는 원본·관리자 키 없이 내용 해시·파생 바이트를 검증한 동일 URL을 웹·공유·소개에 사용한다. 필수 오류는 출력 교체 전에 실패하고 기존 출력을 보존한다. 원본 없는 CI는 명시적 공개 검증 모드를 사용한다. 기본 로컬 모드는 복원한 원본이 필요하다. 재료·아이콘·내용 해시 CSS 생성과 비공개/검토/잘못된 ID 기본 표시를 유지한다. 개발은 preview→Vercel Preview, 확인한 preview의 main 병합은 Production이며 PUBLIC_ORIGIN 운영 값은 Production에만 둔다. 로컬 검증은 커밋·푸시·배포를 하지 않는다. 네이티브는 제외하며 웹 이관의 운영 배포·사용자 링크 공유 확인을 완료했다.

#### Scenario: 에셋 교체

- **WHEN** 같은 재료 또는 환영 그림을 바꿔 빌드한다
- **THEN** 내용 해시 주소를 갱신해 이전 캐시와 구분한다.

#### Scenario: 검증 실행

- **WHEN** verify:local을 실행한다
- **THEN** 로컬 테스트·빌드까지만 실행한다.

#### Scenario: 놀이 이미지 버전 교체

- **WHEN** 승인된 공개 후보의 버전이 바뀐 상태로 웹을 빌드한다
- **THEN** 웹 상세·썸네일·공유·소개 페이지는 같은 불변 버전 경로를 사용하며 다른 ID·비공개 이미지를 포함하지 않는다.

#### Scenario: Storage 이미지 오프라인 캐시

- **WHEN** 서비스 워커가 제어하는 화면에서 허용한 Storage 이미지를 CORS로 로드한 뒤 오프라인으로 연다
- **THEN** 남은 방문 이미지를 표시하고 로컬/Storage 이미지 합계 80개를 유지하며 무관한 origin은 캐시하지 않는다.

#### Scenario: 원격 이미지 장애

- **WHEN** 이미지가 미방문·누락·404/5xx·CORS 실패 또는 opaque 응답이다
- **THEN** 기본 표시를 제공하고 실패 응답을 정상 Storage 캐시로 기록하지 않으며 본문·찜·기록 이용을 막지 않는다.

#### Scenario: Git 이미지 없는 빌드

- **WHEN** 놀이 원본 JPEG·Git·관리자 키가 없는 소스 fixture에서 완전한 공개 자산으로 웹을 빌드한다
- **THEN** 필수 상세/썸네일의 SHA-256·크기·WebP를 검증해 Expo export·공유·PWA 출력을 생성하며 원본을 복원하지 않는다.

#### Scenario: 필수 공개 자산 실패

- **WHEN** 필수 후보/파일 누락·해시/형식 오류·전송·export·후처리·출력 교체가 실패한다
- **THEN** 실패를 반환하고 기존 정상 출력을 유지하거나 복원한다. 복원도 실패하면 직전 출력의 경로와 바이트를 보존하고 임의 삭제하지 않는다.

#### Scenario: 원본 없는 CI 검증

- **WHEN** 놀이 JPEG 없는 checkout에서 공개 설정과 `verify:local --public-images`로 검증한다
- **THEN** 로컬 원본 존재 검사 대신 모든 필수 공개 자산의 해시·크기·WebP를 검증하는 빌드를 실행하고 나머지 회귀·타입·명세 검사와 실패 중단을 유지한다. 공개 입력은 빌드에만 전달하며 관리자 변수·dotenv·분석 전송은 제외한다. 공개 설정이 부족하면 실패하며 기본 로컬 검증으로 우회하지 않는다.

### Requirement: WEB-004 정적 서비스 소개 페이지

웹 빌드 SHALL 앱 경로와 분리된 정적 서비스 소개 페이지 `/intro`를 생성한다. 페이지의 놀이·재료·월령·발달영역 수치는 빌드 시점의 live 놀이와 검수 대기를 제외한 재료 레지스트리에서 계산하며 하드코딩하지 않는다. 화면 이미지는 실제 서비스 웹 화면 캡처를 내용 해시 WebP로 제공한다. 브랜드명은 ‘노리 레시피’로 표기하고, 동작 효과(숫자 세어 올리기·막대 채우기·스크롤 등장·데모 결과 전환)는 동작 줄이기 미설정과 스크립트 실행 시에만 적용해 그 외에는 모든 내용과 최종 수치를 처음부터 보여 주며, 미리 찾아보기 데모는 live 놀이의 공개 상세 링크만 사용하며 검수 중 그림을 노출하지 않는다. 소개 페이지는 분석 스크립트·서비스 워커 등록·외부 폰트를 추가하지 않으며 루트와 앱 경로의 기존 동작을 바꾸지 않는다.

#### Scenario: 데이터 기반 수치

- **WHEN** live 놀이 또는 재료 레지스트리가 바뀐 뒤 웹을 빌드한다
- **THEN** `/intro`의 놀이 수·준비 5분 이내 놀이 수·재료 수·월령 범위·발달영역별 수가 새 데이터로 계산된다.

#### Scenario: 소개 페이지 제공

- **WHEN** 처음 방문한 사용자가 `/intro`를 연다
- **THEN** 앱 온보딩이나 리다이렉트 없이 소개 페이지를 보고, 시작 버튼으로 `/`에, 둘러보기로 `/search`에 이동할 수 있다.

#### Scenario: 미리 찾아보기

- **WHEN** 소개 페이지에서 월령 구간과 재료 칩을 고른다
- **THEN** 해당 월령과 겹치고 필수 재료가 모두 선택된 live 놀이 수와 최대 3개의 공개 상세 링크를 보여 준다. imageStatus=review 놀이는 기본 브랜드 이미지를 쓴다.

#### Scenario: 공유 주소

- **WHEN** Preview 또는 운영 빌드에서 소개 페이지를 생성한다
- **THEN** canonical·OG 주소가 해당 배포 origin의 `/intro`로 채워진다.

#### Scenario: 동작 줄이기와 스크립트 미실행

- **WHEN** 기기의 동작 줄이기가 켜져 있거나 자바스크립트가 꺼진 상태로 `/intro`를 연다
- **THEN** 숨겨진 섹션 없이 모든 내용이 보이고 숫자·막대는 처음부터 최종 값으로 표시된다. 동작 줄이기가 켜져 있으면 재료 띠도 멈춘다.

2026-11-15 실제 Storage의 3개 이미지로 원본/관리자 키 없는 희소 앱 export·화면/OG·CORS 캐시를 확인했다. [실행 보고서](../../changes/migrate-play-images-to-supabase-storage/evidence/storage-pilot-2026-11-15.md)에 범위를 기록하며 실기기 오프라인·공유 봇·호스팅 배포는 미확인이다.

2026-11-15 공개416개 실제 익명 GET·CORS·무결성 및 원본/관리자 키 없는 전체208개 앱 export를 검증했다. [전체 실행 보고서](../../changes/migrate-play-images-to-supabase-storage/evidence/full-upload-2026-11-15.md)는 로컬 확인 결과이며 기본 참조·운영 배포는 유지한다.

2026-11-15 웹 이관의 최종 상태는 [완료 검증](../../changes/migrate-play-images-to-supabase-storage/verification.md)을 따른다. Preview/Production·원본 없는 CI·익명 공유 HTML/이미지6개 체인과 운영 PWA 선택 업데이트/CORS 캐시 해시를 확인했고 사용자가 실제 링크 공유의 정상 표시를 확인했다. 앞의 파일럿/로컬 기록은 당시 검증 범위다. 플랫폼·기종·카카오 공식 도구 로그인 여부는 사용자 확인에 덧붙여 추정하지 않는다.
