# 토스 미니앱

## Purpose

기존 노리 레시피 웹서비스와 저장 데이터를 유지하면서 토스 안에서 보호자가 추천·탐색·놀이 상세·저장·기록을 이용할 수 있도록 실행과 출시 준비의 경계를 정의한다.

## Requirements

### Requirement: TOSS-001 독립 실행과 기존 서비스 보존

토스 대상 SHALL 로그인·결제 없이 승인된 기존 핵심 기능을 별도 정적 번들에서 제공하며 일반 웹/네이티브의 저장 키·guestId·분석 동의·PWA·배포 출력을 보존한다. 토스 번들은 자사 웹을 임베드하거나 리다이렉트하지 않는다.

#### Scenario: 웹과 토스 빌드
- **WHEN** 각각의 대상을 빌드한다
- **THEN** 웹은 기존 동작을 유지하고 토스는 별도 출력에서 토스 런타임을 사용한다.

#### Scenario: 토스 시작 실패
- **WHEN** 사용자 식별이나 저장소 초기화가 실패한다
- **THEN** 재시도 가능한 오류를 표시하며 다른 저장소로 조용히 대체하지 않는다.

### Requirement: TOSS-002 사용자별 기기 저장

토스 대상 MUST 사용자 식별키별로 기기 저장을 분리하고 찜·기록·프로필·삭제 표시·추천 설정을 재접속 후 복원한다. 전체 초기화는 현재 사용자의 서비스 데이터만 지우며 웹·다른 사용자 데이터에 영향을 주지 않는다. 기기 간 자동 동기화나 웹 데이터 이전을 제공한다고 표시하지 않는다.

#### Scenario: 재접속과 사용자 변경
- **WHEN** 같은 사용자가 다시 접속하거나 토스 사용자가 바뀐다
- **THEN** 같은 사용자의 기록을 복원하고 다른 사용자에게 이전 사용자의 정보가 표시되거나 저장되지 않는다.

#### Scenario: 삭제와 실패
- **WHEN** 전체 초기화를 실행하거나 저장이 실패한다
- **THEN** 현재 사용자 서비스 키만 삭제하며 실패는 성공으로 표시하지 않는다.

### Requirement: TOSS-003 토스 내 탐색과 화면 영역

토스 대상 SHALL 발견·탐색·저장·기록·마이의 공통 플로팅 하단 바와 안전 영역을 적용하며 최소44×56px 터치 영역, WEB-006의 선택 라벨·강조 배경·아이콘 스프링과 모션 축소 정책을 유지한다. 뒤로가기는 대화상자·앱 내 이전 화면·최초 화면 종료 순으로 처리한다. 중복 뒤로가기·설치·PWA 업데이트·웹 분석 동의 유도는 표시하지 않는다. 브랜드 헤더는 기존 꽃 로고·노리레시피 크기를 유지하고 공통 가족 요약·월령 단축 버튼·소개 문단은 숨긴다. 월령은 기존 설정·온보딩에서 수정한다. 호스트 상단 영역을 중복 적용하지 않으며 브랜드 상하padding0·홈 링크44px·본문 상단8px와 하단·좌우 안전 여백을 유지한다.

#### Scenario: 직접 상세와 뒤로가기
- **WHEN** 놀이 상세로 직접 진입한 뒤 뒤로간다
- **THEN** 앱 홈으로 이동할 수 있으며 최초 화면에서는 종료하고 대화상자가 열려 있으면 먼저 닫는다.

#### Scenario: 화면 영역 변경
- **WHEN** 안전 영역이 바뀌거나 화면을 이동한다
- **THEN** 좁은 화면에서도 선택 라벨 공간과5개 메뉴의 최소44px 너비·56px 높이를 유지하며 조작부가 가려지지 않고 구독·호출이 중복 누적되지 않는다.

#### Scenario: 공통 상단 요약 제거와 설정 접근
- **WHEN** 토스 미니앱의 화면을 연다
- **THEN** 꽃 로고와 노리레시피가 기존 크기로 표시되고 가족 요약·월령 단축 버튼은 표시하지 않는다. SDK top inset이 바뀌어도 shell 상단padding은0이며 브랜드 홈 링크44px와 본문 상단8px를 유지한다. 기존 내 설정에서 월령을 수정할 수 있다. 일반 웹의 마이 메뉴·홈 월령 안내 정책도 유지한다.

### Requirement: TOSS-004 놀이 딥링크 공유

토스 공유 MUST 공개 놀이 ID만 포함한 정식 토스 딥링크로 생성하고 SDK 공유·클립보드 기능을 사용한다. 개인 입력·검색어·재료 목록·임시 테스트 스킴을 포함하지 않으며 실패 시 자사 웹 링크로 우회하지 않는다.

#### Scenario: 공유 성공과 실패
- **WHEN** 놀이를 공유하거나 공유 링크 생성에 실패한다
- **THEN** 해당 놀이의 토스 공유 링크를 전달하거나 재시도 안내를 제공한다.

### Requirement: TOSS-005 삽화와 개인정보 고지

토스 대상 SHALL 이용 안내에서 놀이·재료 그림이 AI로 만든 참고용 삽화임과 안전 안내를 설명한다. 개별 이미지의 AI 삽화 라벨과 모든 화면 상단의 공통 AI 안내 문단은 표시하지 않는다. 개인정보 안내는 사용자 식별·기기 저장·공개 이미지 요청·공식 SDK 광고·공유·삭제와 기기 저장의 한계를 설명한다. 토스에서는 기존 웹 GA와 개인 입력·기록을 전송하지 않는다.

#### Scenario: 첫 상세 진입과 설정
- **WHEN** 처음 상세 링크로 접속하거나 이용 안내를 연다
- **THEN** 이용 안내에서 AI·안전·개인정보 안내를 확인할 수 있으며 그림 위 라벨이나 콘텐츠 위 공통 AI 안내 문단은 표시하지 않는다.

### Requirement: TOSS-006 검증 가능한 출시 준비물

토스 빌드 MUST 콘솔 appName과 맞출 수 있는 설정, 100MB 이하 앱 번들, 별도 빌드 보고서와 출시 체크리스트를 제공한다. 빌드 실패는 기존 정상 출력을 보존하며 기밀·소스맵·검수 대기 콘텐츠를 번들에 넣지 않는다. 로컬 검증과 콘솔 업로드·QR 실기기·심사·출시 확인을 구분한다. 토스 배포 번들의 JavaScript와 HTML 인라인 스크립트에 eval 참조나 Function 생성자가 있으면 포장 전에 빌드를 거부한다. Expo의 서버 UUID·개발 번들 로더 분기는 토스 배포용 웹 빌드에서만 제외하고 기존 브라우저 경로와 일반 웹/네이티브·Devtools는 유지한다.

#### Scenario: 빌드와 인계
- **WHEN** 토스 빌드·검사를 완료한다
- **THEN** 웹 출력과 분리한 번들을 제공하고 아직 수행하지 않은 외부 확인을 완료로 표시하지 않는다.


#### Scenario: 라이브러리의 동적 코드 실행 유입
- **WHEN** 직접·간접·멤버·계산 속성·이스케이프된 eval 참조 또는 Function 생성자가 배포 JavaScript나 HTML 인라인 스크립트에 포함된다
- **THEN** 실제 실행 여부와 관계없이 포장 전에 실패하고 직전 정상 산출물을 보존한다. 문자열·주석의 설명은 실행 코드로 취급하지 않으며 구문 분석 실패도 차단한다.

#### Scenario: Expo 서버·개발 분기 제외
- **WHEN** 토스 배포용 단일 웹 번들을 만든다
- **THEN** Expo UUID의 서버 require 분기와 분할 번들 로더의 서버·개발 fallback을 소스 변환 단계에서 제거하고 기존 crypto.randomUUID·UUID v5·브라우저 로더 경로는 유지한다. 예상한 라이브러리 구조가 바뀌면 변환을 중단한다. 일반 웹/네이티브·토스 Devtools에는 변환하지 않는다.

### Requirement: TOSS-007 명시적 다음 추천 시작 전면형 광고

토스 대상 SHALL 추천3개 완료·기록 저장·홈 복귀를 축하로 끝내고, 홈에서 사용자가 ‘다음 놀이 3개 시작’을 누르거나3개 완료 후 재료 저장으로 새 회차를 시작할 때 공식 `loadFullScreenAd`·`showFullScreenAd`로 준비된 전면형 광고를 표시한다. 홈 버튼을 누르면 광고와 실제 표시 후24시간 무광고를 안내하는 확인 팝업을 먼저 열고 ‘확인’ 이후에만 광고를 요청하며 재료 선택창 열기·0~2개 완료 상태의 재료 저장·기록 저장 화면에는 광고를 연결하지 않는다. 팝업 제목은 ‘광고 안내’로 표시하고 본문과 버튼 사이에 구분선 없이24px 여백을 둔다. 일반 웹·네이티브에는 광고 SDK를 추가하지 않는다.

#### Scenario: 다음 놀이의 명시적 시작과 닫힘
- **WHEN** 추천3개를 완료한 사용자가 홈 다음 시작 버튼을 누르고 안내 팝업에서 ‘확인’을 선택하며 광고가 준비돼 있고24시간 제한 밖이다
- **THEN** 같은 광고 그룹 ID로 광고를 한 번 표시하고 닫힌 뒤 현재 재료의 다음 회차를 시작한다. 중복 클릭은 한 요청으로 합치고 SDK에는 광고 그룹 ID만 전달한다. 놀이·기록·프로필 식별자는 전달하지 않는다.

#### Scenario: 광고 안내 팝업 취소
- **WHEN** 홈 다음시작 또는 완료 후 재료 저장의 안내 팝업에서 취소·Escape·토스 뒤로가기를 선택하거나 다른 화면으로 이동한다
- **THEN** 팝업만 닫고 광고를 요청하거나 새 회차를 만들지 않는다. 기존3/3과 기록 및 마지막 광고 표시 시각은 유지한다. 재료 편집에서 취소한 경우 선택창을 다시 열어 편집 중 재료를 보존하고 실제 재료 설정은 저장하지 않는다. 확인 시 팝업을 먼저 닫아 광고 SDK의 열린 dialog 차단과 충돌하지 않으며 중복 확인은 한 요청으로 처리한다.

#### Scenario: 완료 후 재료 변경으로 다음 회차 시작
- **WHEN** 추천3개 완료 후 홈 또는 설정에서 재료를 편집하고 재료 선택창에서 새 추천 저장을 누른다
- **THEN** 재료 선택창을 닫아 둔 상태에서 홈 다음시작과 동일한 확인 팝업을 거치며 확인 후에만 광고를 요청한다. 광고 처리 후 선택한 재료로 다음 회차를 저장하고 이전 완료 묶음/누적 기록을 보존한다.24시간 안에는 팝업/광고 없이 저장한다. 저장 실패는 편집 초안으로 돌아가 재시도할 수 있고 중복 클릭은 한 번만 저장한다.

#### Scenario: 실제 표시 후 연속24시간
- **WHEN** SDK의 `show` 이벤트가 발생한다
- **THEN** 해당 시각을 현재 토스 사용자별 기기에 저장하고 그 시각부터24시간 안의 모든 다음 시작은 안내 팝업과 광고 없이 바로 진행한다. 요청·로드·`impression`·자정은 기준이 아니며 재접속에도 제한을 유지한다.24시간 경계부터 다음 명시적 시작이 다시 노출 기회가 된다. 시각 저장 실패에도 현재 세션의 제한은 유지하고 읽기 실패/손상 시 광고 없이 진행한다. 전체 로컬 초기화는 이 시각도 삭제한다.

#### Scenario: 완료·홈 재진입·재료 편집
- **WHEN** 세 번째 놀이 기록 저장·축하·홈 재진입·재실행·재료 선택창 열기 또는0~2개 완료 상태의 재료 저장을 한다
- **THEN** 광고를 표시하지 않는다. 완료 기록·도장·달성 묶음·추천 회차는 기존 정책대로 보존하며 날짜만 바뀌어 초기화하지 않는다.

#### Scenario: 미준비·실패·늦은 콜백
- **WHEN** 다음 시작 때 광고가 미지원·로드 중·오류·표시 실패이거나 화면이 숨겨져 있다
- **THEN** 새 추천은 바로 진행하고 해당 시작 기회의 광고를 뒤늦게 표시하거나 자동 재시도하지 않는다. 실제 화면 표시가 없으면24시간 제한을 소비하지 않는다. SDK 콜백이 전혀 오지 않으면 요청 후5초에 진행하고 늦은 콜백은 무시한다.

#### Scenario: 닫힘 콜백 누락과 화면 이탈
- **WHEN** 실제 표시 후 `dismissed`가 누락되거나 사용자가 홈을 떠난다
- **THEN** 광고 표시 중 앱 이탈 후 유효 사용자로 복귀하면 진행하고 복귀 신호도 없으면 표시 후60초에 다음 추천을 준비한다. SDK 광고 자체를 강제로 닫거나 조작하지 않는다. 홈을 떠난 요청은 나중에 새 회차를 만들지 않으며 런타임 종료는 구독·타이머·대기를 정리한다.

#### Scenario: 테스트와 운영 빌드
- **WHEN** 개발 실행이나 기본 토스 번들을 만든다
- **THEN** 공식 전면형 테스트 ID를 사용한다. 운영 모드는 별도 지정과 콘솔 광고 그룹 ID를 요구하며 번들 보고서에 모드·그룹 ID·다음 추천 시작 지면을 남긴다. 실제 광고 클릭·노출을 자동화하지 않으며 콘솔 QR iOS·Android 검증을 로컬 모의 검증과 구분한다.
