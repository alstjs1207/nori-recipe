# 토스 미니앱

## Purpose

기존 노리 레시피 웹서비스와 저장 데이터를 유지하면서 토스 안에서 보호자가 추천·탐색·놀이 상세·저장·기록을 이용할 수 있도록 실행과 출시 준비의 경계를 정의한다.

## Requirements

### Requirement: TOSS-001 독립 실행과 기존 서비스 보존

토스 대상 SHALL 로그인·결제 없이 승인된 기존 핵심 기능을 별도 정적 번들에서 제공하며 일반 웹/네이티브의 저장 키·guestId·분석 동의·PWA·배포 출력을 보존한다. 토스 번들은 자사 웹을 임베드하거나 리다이렉트하지 않는다.

#### Scenario: 웹과 토스 빌드
- **WHEN** 각각의 대상을 빌드한다
- **THEN** 웹은 기존 동작을 유지하고 토스는 별도 출력에서 토스 런타임을 사용한다.

#### Scenario: 토스 시작 실패
- **WHEN** 사용자 식별이나 저장소 초기화가 실패한다
- **THEN** 재시도 가능한 오류를 표시하며 다른 저장소로 조용히 대체하지 않는다.

### Requirement: TOSS-002 사용자별 기기 저장

토스 대상 MUST 사용자 식별키별로 기기 저장을 분리하고 찜·기록·프로필·삭제 표시·추천 설정을 재접속 후 복원한다. 전체 초기화는 현재 사용자의 서비스 데이터만 지우며 웹·다른 사용자 데이터에 영향을 주지 않는다. 기기 간 자동 동기화나 웹 데이터 이전을 제공한다고 표시하지 않는다.

#### Scenario: 재접속과 사용자 변경
- **WHEN** 같은 사용자가 다시 접속하거나 토스 사용자가 바뀐다
- **THEN** 같은 사용자의 기록을 복원하고 다른 사용자에게 이전 사용자의 정보가 표시되거나 저장되지 않는다.

#### Scenario: 삭제와 실패
- **WHEN** 전체 초기화를 실행하거나 저장이 실패한다
- **THEN** 현재 사용자 서비스 키만 삭제하며 실패는 성공으로 표시하지 않는다.

### Requirement: TOSS-003 토스 내 탐색과 화면 영역

토스 대상 SHALL 공통 내비게이션, 플로팅 탭바와 안전 영역을 적용한다. 뒤로가기는 열린 대화상자·앱 내 이전 화면을 처리하고 최초 화면에서는 미니앱을 닫는다. 중복 뒤로가기·설치 유도·PWA 업데이트·웹 분석 동의 유도를 표시하지 않는다. 콘텐츠 위에는 기존 꽃 로고와 노리레시피 글자를 기존 웹의 크기로 표시하는 브랜드 헤더를 제공한다. 모바일은 꽃32px·글자24px이며 별도 축소하지 않는다. 가족 요약·월령 단축 버튼·소개 문단은 표시하지 않으며 월령은 기존 내 설정과 온보딩에서 수정할 수 있다. 안전 영역은 한 번만 적용하고 브랜드 헤더 아래 본문 상단 여백은20px로 맞춘다.

#### Scenario: 직접 상세와 뒤로가기
- **WHEN** 놀이 상세로 직접 진입한 뒤 뒤로간다
- **THEN** 앱 홈으로 이동할 수 있으며 최초 화면에서는 종료하고 대화상자가 열려 있으면 먼저 닫는다.

#### Scenario: 화면 영역 변경
- **WHEN** 안전 영역이 바뀌거나 화면을 이동한다
- **THEN** 조작부가 가려지지 않고 구독·호출이 중복 누적되지 않는다.

#### Scenario: 공통 상단 요약 제거와 설정 접근
- **WHEN** 토스 미니앱의 화면을 연다
- **THEN** 꽃 로고와 노리레시피가 기존 크기로 표시되고 가족 요약·월령 단축 버튼은 표시하지 않는다. 상단 안전 영역을 중복 적용하지 않으며 기존 내 설정에서 월령을 수정할 수 있다. 일반 웹의 프로필 헤더는 유지한다.

### Requirement: TOSS-004 놀이 딥링크 공유

토스 공유 MUST 공개 놀이 ID만 포함한 정식 토스 딥링크로 생성하고 SDK 공유·클립보드 기능을 사용한다. 개인 입력·검색어·재료 목록·임시 테스트 스킴을 포함하지 않으며 실패 시 자사 웹 링크로 우회하지 않는다.

#### Scenario: 공유 성공과 실패
- **WHEN** 놀이를 공유하거나 공유 링크 생성에 실패한다
- **THEN** 해당 놀이의 토스 공유 링크를 전달하거나 재시도 안내를 제공한다.

### Requirement: TOSS-005 삽화와 개인정보 고지

토스 대상 SHALL 이용 안내에서 놀이·재료 그림이 AI로 만든 참고용 삽화임과 안전 안내를 설명한다. 개별 이미지의 AI 삽화 라벨과 모든 화면 상단의 공통 AI 안내 문단은 표시하지 않는다. 개인정보 안내는 사용자 식별·기기 저장·공개 이미지 요청·공식 SDK 광고·공유·삭제와 기기 저장의 한계를 설명한다. 토스에서는 기존 웹 GA와 개인 입력·기록을 전송하지 않는다.

#### Scenario: 첫 상세 진입과 설정
- **WHEN** 처음 상세 링크로 접속하거나 이용 안내를 연다
- **THEN** 이용 안내에서 AI·안전·개인정보 안내를 확인할 수 있으며 그림 위 라벨이나 콘텐츠 위 공통 AI 안내 문단은 표시하지 않는다.

### Requirement: TOSS-006 검증 가능한 출시 준비물

토스 빌드 MUST 콘솔 appName과 맞출 수 있는 설정, 100MB 이하 앱 번들, 별도 빌드 보고서와 출시 체크리스트를 제공한다. 빌드 실패는 기존 정상 출력을 보존하며 기밀·소스맵·검수 대기 콘텐츠를 번들에 넣지 않는다. 로컬 검증과 콘솔 업로드·QR 실기기·심사·출시 확인을 구분한다.

#### Scenario: 빌드와 인계
- **WHEN** 토스 빌드·검사를 완료한다
- **THEN** 웹 출력과 분리한 번들을 제공하고 아직 수행하지 않은 외부 확인을 완료로 표시하지 않는다.


### Requirement: TOSS-007 추천 세트 완료 전면형 광고

토스 대상 SHALL 현재 추천 3개 중 마지막 미완료 놀이의 새 기록 저장이 성공한 뒤 홈으로 돌아오는 시점에 공식 `loadFullScreenAd`·`showFullScreenAd`로 전면형 광고를 최대 한 번 표시한다. 기록은 광고와 무관하게 먼저 저장하고 기존 완료 메시지·축하 효과·새 추천 기능을 유지한다. 기록 저장 화면에서 완료 후 광고가 표시될 수 있음을 안내한다. 일반 웹·네이티브에는 광고 SDK를 추가하지 않는다.

#### Scenario: 세 번째 놀이 저장 후 홈 복귀
- **WHEN** 현재 추천은 중복 없는 3개이고 새 저장 기록을 제외하면 미완료였던 세트가 모두 완료되며 미리 로드한 광고가 준비돼 있다
- **THEN** 같은 광고 그룹 ID로 광고를 한 번 표시하고 닫힘 뒤 다음 광고를 순차 로드한다. 놀이·기록·프로필 식별자는 광고 SDK에 전달하지 않는다.

#### Scenario: 반복 진입과 과거 기록
- **WHEN** 일반 홈 재진입·재실행·이미 완료된 놀이의 재기록·추천 외 놀이 완료·3개 미만 세트 완료가 발생한다
- **THEN** 광고를 표시하지 않는다. 노출 판단은 기존 완료 이력을 유지하며 날짜가 바뀌었다는 이유로 기록이나 세트를 초기화하지 않는다.

#### Scenario: 광고 미지원과 실패
- **WHEN** 광고가 미지원·로드 중·오류·노출 실패이거나 홈을 떠났거나 기기가 숨김 상태다
- **THEN** 해당 완료 기회의 광고를 건너뛰고 늦게 표시하거나 자동 재시도하지 않는다. 저장·축하·탐색·뒤로가기를 광고 때문에 막지 않으며 콜백 구독을 해제한다.

#### Scenario: 테스트와 운영 빌드
- **WHEN** 개발 실행이나 기본 토스 번들을 만든다
- **THEN** 공식 전면형 테스트 ID를 사용한다. 운영 모드는 별도 지정과 콘솔 광고 그룹 ID를 요구하며 보고서에 모드·그룹·위치를 남긴다. 실제 테스트 광고는 콘솔 QR의 토스앱에서 확인하고 모의 SDK 결과와 구분한다.
