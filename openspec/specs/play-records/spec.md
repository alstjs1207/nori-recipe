# 찜·놀이 완료·피드백·기록

## Purpose

현재 코드·테스트와 기존 제품 정책을 대조한 계약이다. 검증 공백은 `openspec/known-gaps.md`, 완료 근거는 `openspec/completed-work.md`를 참고한다.

## Requirements

### Requirement: LOG-001 완료 피드백 검증과 기록

서비스 MUST 알려진 놀이 ID, 정수 별점 1~5, 허용 반응 및 100자 이하 메모를 검증한 뒤 완료 기록과 개인화 문맥을 저장한다. 새 반응 네 종류와 과거 반응 네 종류의 읽기 호환을 유지한다. 앱 실행 중 guest/놀이별 미저장 초안은 화면 이동·놀이 변경·재진입으로 지우지 않으며 같은 기록 화면의 새 진입은 입력을 유지하고 상단에서 시작한다. 성공한 제출 버전의 초안만 지우고 실패 또는 저장 중 추가 입력은 보존한다. 전체 데이터 초기화는 해당 guest 초안도 지운다. 초안을 완료 기록으로 집계하거나 분석 전송하지 않으며 영구 저장·동기화로 해석하지 않는다. 네이티브는 쓰기 배치, 웹은 저장 실패 시 원래 배열 복원을 시도한다.

#### Scenario: 잘못된 입력

- **WHEN** 별점 0 또는 6, 알 수 없는 반응, 101자 메모를 제출한다
- **THEN** 저장 전에 거부한다.

#### Scenario: 정상 완료

- **WHEN** 유효한 별점·반응을 저장한다
- **THEN** 새 완료 ID와 시간 및 갱신된 문맥을 저장한다.

#### Scenario: 다른 놀이 기록 진입

- **WHEN** 기록 화면을 아래로 스크롤한 뒤 다른 놀이의 기록 화면에 진입한다
- **THEN** 이전 스크롤 위치를 가져오지 않고 맨 위에서 시작하며 별점·반응·메모는 해당 guest와 놀이의 미저장 초안을 사용한다.

#### Scenario: 미저장 초안과 저장 버전

- **WHEN** 놀이 A의 초안을 입력하고 B로 이동했다 돌아오거나 저장에 실패한다
- **THEN** A의 별점·반응·메모를 보존하며 성공한 제출 뒤에도 그 사이 새로 편집한 입력은 지우지 않는다.

#### Scenario: 추천 회차와 누적 기록 분리

- **WHEN** 추천 놀이를 완료하거나 과거에 한 놀이를 새 회차에서 다시 완료한다
- **THEN** 매번 정상 누적 기록을 보존하고 현재 회차에는 같은 놀이를 한 번만 집계한다. 새 추천은 누적 기록을 지우지 않는다. 추천 외 놀이 기록은 현재 추천을 교체하거나 완료 수를 늘리지 않는다.

### Requirement: LOG-002 개인화 신호와 진단 경계

서비스 SHALL 높은 별점·긍정 반응과 낮은 별점·도움 필요 반응을 관련 발달 영역의 userFeedback·devGaps에 반영하며 점수는 0~100으로 제한한다. 이는 추천 신호이며 아이의 발달 진단이나 구현되지 않은 유료 발달 리포트를 뜻하지 않는다.

#### Scenario: 양수 피드백

- **WHEN** 4~5점 또는 집중·스스로 반응을 저장한다
- **THEN** 관련 추천 신호를 갱신한다.

#### Scenario: 점수 한계

- **WHEN** 반복 피드백으로 경계값을 넘으려 한다
- **THEN** 0~100 안으로 제한한다.

### Requirement: LOG-003 찜·기록·통계의 로컬 범위

서비스 SHALL guestId에 속한 활성 찜·완료·발달 로그를 조회하고 찜 전환과 기록·영역 통계를 제공한다. 통계의 기간 경계와 표시 시간대는 현재 구현을 따르며 계정 간 공유나 동기화를 제공하지 않는다.

#### Scenario: 다른 게스트

- **WHEN** 다른 guestId의 기록을 조회한다
- **THEN** 현재 게스트의 활성 기록과 섞지 않는다.

#### Scenario: 삭제 표시

- **WHEN** deletedAt이 있는 기록이 있다
- **THEN** 활성 조회·통계에서 제외한다.

### Requirement: LOG-004 완성한 놀이 묶음과 기록 보기

서비스 SHALL 홈 회차에서 실제 완료한 최종3개를 달성 날짜별 묶음으로 기기에 보존한다. 기록은 기본 최근3묶음·개별 놀이·월별 전체 보기를 제공하며 사진 아래 놀이 제목과 강조한 달성 날짜를 표시한다. 전체 기록 기준 횟수·날짜 수·경험 영역 수와 접을 수 있는7개 발달영역 ‘이런 놀이를 함께했어요’를 유지한다. 기존 guest·활성 기록·삭제 경계를 따르며 발달 진단이나 동기화를 뜻하지 않는다.

#### Scenario: 교체한 놀이로 묶음 완성

- **WHEN** A/B 완료 후 C를 D로 바꾸고 D의 실제 기록 저장이 성공한다
- **THEN** A/B/D 이미지와 제목을 달성 날짜에 한 묶음으로 보존한다. 새 회차·같은 놀이 재추천·중복 기록은 이전 묶음을 지우거나 중복 생성하지 않는다.

#### Scenario: 기본 화면과 전체 보기

- **WHEN** 여러 달에 완성한 묶음이 쌓인다
- **THEN** 기본 보기는 최신3묶음만 달성 날짜별로 표시하고 같은 날의 여러 묶음을 모은다. 전체 보기에서 월을 선택해 과거 묶음을 조회하며 개별 놀이 기록은 별도 보기에서8개씩 더 불러온다.

#### Scenario: 영역 요약

- **WHEN** 완료 묶음 또는 개별 놀이 보기를 연다
- **THEN** 전체 누적 기록으로 요약·7개 영역별 횟수를 표시한다. 한 놀이의 복수 영역을 허용하며 영역을 눌러 관련 놀이를 탐색하고 영역 패널은 접거나 펼칠 수 있다.

#### Scenario: 미완료·실패·삭제·다른 게스트

- **WHEN** 회차가 부분 완료이거나 세 번째 활동 쓰기가 실패하거나 참조 기록이 삭제되었거나 guest가 다르다
- **THEN** 실제 활성 완료 기록3개가 확인되지 않는 묶음은 표시하지 않는다. 영구 저장된 참조와 실제 활동 기록을 대조해 재실행·재시도에도 오완료를 만들지 않는다. 단순 누적 기록을 임의의3개씩 묶어 과거 달성으로 수입하지 않는다.
