# 같은 재료로 다음 추천 설계안

## Context

현재 홈은 추천 ID와 문맥 키를 AsyncStorage에 고정하고, 웹 완료 안내의 ‘새 추천 받기’는 재료 picker를 연다. 완료 표시는 놀이별 최신 완료 시각을 사용한다. `clearPinnedHomeRecommendations`는 보호자 확인도 지우므로 단순 초기화만으로 다음 세트 정책을 구현할 수 없다.

REC-006을 다루는 `clarify-home-set-lifecycle`에 후보 수·수명·완료 기준 검증이 남아 있다. 본 변경은 그 과제의 후속 기능이며 해당 계약을 먼저 조율한다. 현재 specs와 HOME_RECOMMENDATION_RULES는 그대로 유지한다.

## Goals / Non-Goals

- 목표: REC-007의 명시적 전환과 실패 복구를 기존 REC-001~REC-005 위에 추가한다.
- 제외: 미완료 카드 교체, 매일 자동 교체, 준비 조건을 완화한 새로움 우선 추천, 완료 로그 초기화.

## Decisions

1. **완료 이후 명시적 다음 세트**: 자동 재추첨 대신 CTA에서만 전환한다. 미완료 세트 고정 규칙과 일치시키고, 새 추천·재료 편집 버튼을 구분한다. 기존 0~2개 세트의 완료/전환 가능 조건은 REC-006 정책 결정에 의존한다.
2. **추천 우선순위 유지**: 직전 세트 ID를 다양성 문맥에 전달하고 동등한 재료 우선순위에서 대안을 우선한다. 직전 ID를 안전 필터처럼 무조건 제거하면 더 나쁜 재료 후보가 승격될 수 있어 채택하지 않는다. 일부 중복은 안내하고, 완전히 같으면 전환하지 않는다.
3. **세트 단위 상태**: 세트 ID·생성 시각·추천 ID·문맥 키를 하나의 버전 있는 snapshot으로 보관하는 안을 사용한다. 세트 생성 이후 완료만 새 세트 완료로 판단해, 이전 기록이 있는 재선정 놀이가 즉시 완료되는 문제를 막는다. 과거 저장 세트의 기존 완료 표시는 이관 시 보존하고 REC-006 회귀와 함께 검증한다.
4. **안전 재평가**: 새 세트의 상위 월령 후보는 기존 보호자 확인을 자동 재사용하지 않는다. 새 확인을 받기 전에는 기본 월령 후보만 사용한다. 콘텐츠 해시·재료·월령 변경 시 기존 자격을 유지하지 않는다.
5. **쓰기 성공 후 교체**: 전환 중 중복 요청을 잠그고 재료/월령 등 문맥이 바뀌면 오래된 결과를 폐기한다. 저장 성공 후 화면을 교체하고 실패·대안 없음에는 기존 snapshot과 선택 재료를 보존한다.

## Risks / Trade-offs

- [후보 수·수명 정책 충돌] → REC-006·GAP-001·GAP-002를 구현 선행 조건으로 추적하고 두 change가 같은 규칙을 서로 다르게 확정하지 않게 한다.
- [추천 수를 맞추기 위한 안전 완화] → 기존 필터 회귀와 0~3개 후보 fixture로 금지한다.
- [재선정 놀이가 과거 완료 이력으로 완료됨] → 세트 생성 전후 완료 시각·재실행·부분 중복 시나리오를 통합 검증한다.

## Migration Plan

- 기존 핀 키를 읽어 호환 snapshot으로 이관하고 검증된 쓰기 후 전환한다. 기존 guestId·찜·완료 로그는 수정하지 않는다.
- 실패 시 기존 저장 세트로 복귀하며 유효한 세트를 알고리즘 변경만으로 폐기하지 않는다.
- 후속 구현에서 현재 recommendations 명세·HOME_RECOMMENDATION_RULES·policy-map을 함께 갱신한다. 수집 콘텐츠·이미지·검수 해시와 분석 허용 목록은 유지한다.
- 웹·네이티브에서 동일한 상태 전이를 검증한다. Preview/실기기 확인과 운영 배포는 분리하며 이번 계획에 배포 실행을 포함하지 않는다.
