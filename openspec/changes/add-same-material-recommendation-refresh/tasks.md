# 같은 재료로 다른 추천 받기 — 작업 예정·미착수

계획 문서만 등록했다. 구현·검증 체크는 아직 없다. 제안 계약 REC-007을 추가하되 REC-001~REC-005를 보존하며, REC-006의 선행 정책 결정을 완료하기 전 추천 규칙을 변경하지 않는다.

## 1. 세트 수명 계약과 상태

- [ ] 1.1 `clarify-home-set-lifecycle`의 REC-006·GAP-001·GAP-002와 세트 완료 기준·0~2개 후보 동작을 조율한다. 합의한 결과를 두 change의 설계/delta와 HOME_RECOMMENDATION_RULES 변경안에 일치시켜 선행 조건 해소를 검증한다.
- [ ] 1.2 세트 ID·생성 시각·추천 ID·문맥 키의 snapshot과 완료 기준을 구현한다. 과거 핀·완료 표시 보존, 재선정 놀이의 과거 완료와 새 완료 구분, 이관 실패·재실행 fixture 회귀로 검증한다.
- [ ] 1.3 세트 상태의 구현·테스트 근거를 REC-004/REC-007 명세·policy-map과 연결한다. 기존 미완료 세트가 일반 점수·날짜 변화로 바뀌지 않는 회귀와 `pnpm spec:check`로 검증한다.

## 2. 다음 추천과 홈 동선

- [ ] 2.1 직전 세트를 문맥으로 전달하는 대안 선택을 구현한다. 월령·제외 재료·안전·재료 우선순위, 동등 후보의 새 놀이 우선, 일부/전체 중복·후보 부족 회귀로 검증한다.
- [ ] 2.2 새 세트의 상위 월령 보호자 확인 재사용을 차단하고 준비 확인·해시 변경 검증을 연결한다. 미확인 상태에서 상위 후보가 나오지 않는 추천 회귀로 검증한다.
- [ ] 2.3 웹·네이티브 홈에 완료 후 다음 추천 CTA와 별도 재료 편집, 대안 부족·전환 실패·중복 요청 처리를 구현한다. 미완료 세트 유지·같은 재료 유지·문맥 변경 경합·저장 성공 후 교체를 화면/상태 통합 회귀로 검증한다.
- [ ] 2.4 확정 동작을 recommendations 현재 명세·HOME_RECOMMENDATION_RULES·policy-map·필요한 source-index에 반영하고 선행 change와 중복/충돌이 없는지 대조한다. 관련 추천 회귀와 `pnpm spec:check`로 검증한다.

## 3. 통합 검증

- [ ] 3.1 Node 24/pnpm 10.33.0에서 `pnpm verify:local`을 실행하고 추천 엔진·화면·저장 회귀의 실행 결과를 날짜·명령과 함께 이 change에 기록한다.
- [ ] 3.2 웹 로컬/Preview와 네이티브 검증 환경에서 첫 세트 완료→다음 세트→부분 중복→재실행→다음 세트 완료를 확인한다. 사용 환경·0~3개 후보 결과·실패 재시도·미확인 범위를 기록한다.
