## MODIFIED Requirements

### Requirement: WEB-002 설정의 설치·오프라인·선택 업데이트

PWA SHALL 설정의 앱처럼 이용하기에서 설치 또는 수동 안내를 제공하고 설치 후 상태를 표시한다. 버전별 앱 셸·방문 이미지 캐시를 사용하고 이미지 캐시는 최대 80개로 제한한다. 새 버전은 사용자의 새 버전 열기 선택으로 적용하며 모든 미방문 화면·이미지의 오프라인 제공을 보장하지 않는다. 설치된 웹 앱은 standalone 모드와 운영체제가 제공한 viewport를 사용하고 상하좌우 안전 영역에 조작부가 가려지지 않아야 한다. 첫 방문·설정·일반 화면의 하단 메뉴는 공통 셸에서 한 번만 표시하고 메뉴가 있을 때 하단 안전 여백은 메뉴에서만 적용한다. 상세·피드백에서는 메뉴를 숨긴다. iPhone 수동 안내는 웹 앱으로 열기 선택을 포함한다.

Storage 캐시는 허용 origin·공개 버킷의 익명 CORS 이미지로 제한하고 실패는 기본 표시한다.

#### Scenario: 오프라인

- **WHEN** 이미 방문한 앱을 오프라인으로 연다
- **THEN** 캐시된 셸·미디어를 사용한다.

#### Scenario: 업데이트

- **WHEN** 새 서비스 워커가 대기한다
- **THEN** 사용자 동작 후 SKIP_WAITING으로 적용한다.

#### Scenario: 설치 화면 영역

- **WHEN** iPhone 홈 화면에서 독립 웹 앱으로 연다
- **THEN** 앱 배경이 화면을 채우며 헤더·하단 메뉴·상세 하단 버튼은 안전 영역 안에 표시된다.

#### Scenario: 브라우저 바로가기

- **WHEN** 브라우저 모드에서 설치 안내를 연다
- **THEN** Safari 공유 메뉴·홈 화면에 추가·웹 앱으로 열기 및 홈 화면 실행을 안내하며 저장소를 삭제하도록 요구하지 않는다.

#### Scenario: 첫 방문 하단 메뉴

- **WHEN** 아이 정보가 없는 상태로 첫 실행하거나 /start를 연다
- **THEN** 모바일 첫 방문 화면에도 발견·탐색·저장·기록 메뉴가 표시되며 프로필을 강제로 저장하지 않고 탐색할 수 있다.

#### Scenario: 공통 메뉴와 하단 여백

- **WHEN** 첫 방문·설정·발견·탐색을 오가거나 화면 크기가 바뀐다
- **THEN** 하단 메뉴는 한 번만 표시되고 앱 viewport 하단에 맞춰지며 콘텐츠와 메뉴에서 안전 여백을 중복 적용하지 않는다. 상세·피드백에서는 메뉴 없이 콘텐츠의 안전 여백을 유지한다.

#### Scenario: Storage 캐시 허용 경계

- **WHEN** 설정한 origin·공개 버킷의 불변 버전 이미지 요청을 처리한다
- **THEN** 성공한 읽기 가능한 CORS 이미지만 캐시하고 오류·opaque·비이미지·redirect·무관한 origin·비공개/인증/서명 경로는 제외한다. 로컬/Storage 미디어 합계 80개와 선택 업데이트를 유지한다. 현재 검증은 로컬 fixture이며 실제 Supabase 접근 권한·CORS의 완료 증거가 아니다.


#### Scenario: 준비 후 첫 오프라인 기본 화면

- **WHEN** 온라인에서 앱 셸 준비를 마친 뒤 처음 오프라인으로 홈·시작·설정/안내를 연다
- **THEN** 방문 이력 없이 기본 화면과 안내를 표시한다. 전체 이미지 선저장은 요구하지 않으며 미방문 이미지는 기본 표시, 방문 미디어는80개 제한을 유지한다.

#### Scenario: 기본 화면 준비 상태

- **WHEN** 최초 셸 설치가 진행·완료·실패하거나 기존 활성 셸이 있는 상태로 재실행한다
- **THEN** 준비 중·기본 화면 준비 완료·실패를 구분하고 실패 설치를 완료로 표시하지 않는다. 기존 활성 셸은 보존하며 새 버전은 사용자 선택 후 적용한다.

### Requirement: WEB-003 에셋 준비와 브랜치 배포 경계

빌드 SHALL 놀이 원본 JPEG를 비공개 Storage와 로컬 검수 경로에 보존하고 Git 원본 없이 검증된 공개 상세·썸네일을 참조할 수 있어야 한다. 재료·아이콘·내용 해시 CSS 생성과 놀이·환영 이미지의 버전 구분을 유지한다. 웹 화면·공유 메타데이터는 같은 승인 이미지 버전을 사용하고, 허용된 Storage 이미지의 방문 캐시와 최대 80개 제한을 유지한다. 개발은 preview→Vercel Preview, 확인한 preview의 main 병합은 Production으로 구분한다. PUBLIC_ORIGIN 운영 값은 Production에만 설정한다. 로컬 검증 명령은 커밋·푸시·공개 배포를 수행하지 않는다.

#### Scenario: 에셋 교체

- **WHEN** 같은 재료 또는 환영 그림을 바꿔 빌드한다
- **THEN** 내용 해시 주소를 갱신해 이전 캐시와 구분한다.

#### Scenario: 검증 실행

- **WHEN** verify:local을 실행한다
- **THEN** 로컬 테스트·빌드까지만 실행한다.

#### Scenario: 놀이 이미지 버전 교체

- **WHEN** 검수 승인된 놀이 이미지의 새 버전을 게시하고 빌드한다
- **THEN** 상세·썸네일·공유 메타데이터에 해당 버전의 경로를 사용하며 이전 버전 캐시와 구분한다.

#### Scenario: Storage 이미지 오프라인 캐시

- **WHEN** 사용자가 공개 Storage 이미지를 정상 로드한 뒤 PWA를 오프라인으로 다시 연다
- **THEN** 캐시에 남은 방문 이미지를 표시하고 미디어 캐시는 최대 80개로 유지한다. 무관한 외부 origin은 캐시 허용 대상에 추가하지 않는다.

#### Scenario: 원격 이미지 장애

- **WHEN** 캐시되지 않은 이미지가 없거나 Storage 요청이 실패한다
- **THEN** 기본 표시를 제공하며 놀이 본문 열람·찜·기록 이용을 막지 않는다. 원본 공개나 로그인 강제로 대체하지 않는다.

#### Scenario: Git 이미지 없는 빌드

- **WHEN** 놀이 JPEG가 없는 새 checkout에서 자산 준비와 웹 빌드를 실행한다
- **THEN** 매니페스트에 맞는 서비스 자산으로 재현하고 온라인 셸 준비 후 첫 오프라인 실행에서 기본 화면·안내를 열 수 있다. 필수 자산 준비 실패 시 배포용 빌드를 중단하고 기존 배포를 유지한다.

#### Scenario: 필수 공개 자산 실패

- **WHEN** 필수 후보/파일 누락·해시/형식 오류·전송·export·후처리·출력 교체가 실패한다
- **THEN** 실패를 반환하고 기존 정상 출력을 유지하거나 복원한다. 복원도 실패하면 직전 출력의 경로와 바이트를 보존하고 임의 삭제하지 않는다.
