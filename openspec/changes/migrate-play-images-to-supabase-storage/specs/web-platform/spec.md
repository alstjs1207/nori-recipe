## MODIFIED Requirements

### Requirement: WEB-003 에셋 준비와 브랜치 배포 경계

빌드 SHALL 놀이 원본 JPEG를 비공개 Storage와 로컬 검수 경로에 보존하고 Git 원본 없이 검증된 공개 상세·썸네일을 참조할 수 있어야 한다. 재료·아이콘·내용 해시 CSS 생성과 놀이·환영 이미지의 버전 구분을 유지한다. 웹 화면·공유 메타데이터는 같은 승인 이미지 버전을 사용하고, 허용된 Storage 이미지의 방문 캐시와 최대 80개 제한을 유지한다. 네이티브는 서비스용 이미지를 빌드 시 준비해 오프라인 표시를 보존한다. 개발은 preview→Vercel Preview, 확인한 preview의 main 병합은 Production으로 구분한다. PUBLIC_ORIGIN 운영 값은 Production에만 설정한다. 로컬 검증 명령은 커밋·푸시·공개 배포를 수행하지 않는다.

#### Scenario: 에셋 교체

- **WHEN** 같은 재료 또는 환영 그림을 바꿔 빌드한다
- **THEN** 내용 해시 주소를 갱신해 이전 캐시와 구분한다.

#### Scenario: 검증 실행

- **WHEN** verify:local을 실행한다
- **THEN** 로컬 테스트·빌드까지만 실행한다.

#### Scenario: 놀이 이미지 버전 교체

- **WHEN** 검수 승인된 놀이 이미지의 새 버전을 게시하고 빌드한다
- **THEN** 상세·썸네일·공유 메타데이터에 해당 버전의 경로를 사용하며 이전 버전 캐시와 구분한다.

#### Scenario: Storage 이미지 오프라인 캐시

- **WHEN** 사용자가 공개 Storage 이미지를 정상 로드한 뒤 PWA를 오프라인으로 다시 연다
- **THEN** 캐시에 남은 방문 이미지를 표시하고 미디어 캐시는 최대 80개로 유지한다. 무관한 외부 origin은 캐시 허용 대상에 추가하지 않는다.

#### Scenario: 원격 이미지 장애

- **WHEN** 캐시되지 않은 이미지가 없거나 Storage 요청이 실패한다
- **THEN** 기본 표시를 제공하며 놀이 본문 열람·찜·기록 이용을 막지 않는다. 원본 공개나 로그인 강제로 대체하지 않는다.

#### Scenario: Git 이미지 없는 빌드

- **WHEN** 놀이 JPEG가 없는 새 checkout에서 자산 준비와 웹·네이티브 빌드를 실행한다
- **THEN** 매니페스트에 맞는 서비스 자산으로 재현하고 네이티브에서는 준비된 이미지를 오프라인 표시할 수 있다. 필수 자산 준비 실패 시 배포용 빌드를 중단하고 기존 배포를 유지한다.
