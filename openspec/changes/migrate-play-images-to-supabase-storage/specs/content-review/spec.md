## MODIFIED Requirements

### Requirement: CON-004 놀이 이미지의 비공개 원본과 공개 서비스 자산

서비스 MUST 놀이 원본을 비공개 Storage에 보관하고 승인된 live 놀이의 서비스용 상세·썸네일만 공개 제공한다. 이미지 업로드·교체·삭제는 관리자 권한으로 제한하며, 공개 앱·매니페스트·번들·로그에 관리자 자격 증명과 원본 접근용 서명 URL을 포함하지 않는다. 이용자는 로그인 없이 공개 이미지를 볼 수 있다.

#### Scenario: 원본에 대한 비인가 접근

- **WHEN** 로그인하지 않은 방문자 또는 관리자 권한이 없는 클라이언트가 원본을 조회하거나 이미지를 변경·삭제하려 한다
- **THEN** 작업을 거부하며 원본 버킷을 공개로 전환하거나 공개 클라이언트에 관리자 자격 증명을 제공하지 않는다.

#### Scenario: 승인된 서비스 이미지 조회

- **WHEN** 방문자가 공개 놀이 상세·목록 또는 공유 링크를 연다
- **THEN** 로그인이나 만료되는 서명 URL 없이 승인된 축소 이미지를 볼 수 있고 원본 파일은 전달받지 않는다.

#### Scenario: 초안과 검토 중 이미지

- **WHEN** 놀이가 draft·archived이거나 이미지가 review 상태다
- **THEN** 신규 공개 이미지 게시와 앱의 해당 이미지 참조를 제외하고 기존 기본 표시 정책을 유지한다. 원본을 업로드한 사실만으로 승인·live 상태를 바꾸지 않는다.

#### Scenario: 관리 경계

- **WHEN** 관리 도구를 기본 옵션 또는 디렉터리 fixture 모드로 실행한다
- **THEN** 기본 dry-run은 객체와 파일을 쓰지 않고 환경변수만으로 원격 접속을 활성화하지 않으며, 공개 후보에 원본 접근 정보와 자격 증명을 포함하지 않는다.

### Requirement: CON-005 놀이 이미지 이관의 무결성과 검수 호환성

이관 도구 SHALL 놀이 ID별 원본·파생 이미지 해시와 저장 경로·버전을 검증하고 기존 검수 승인과 연결한다. 원격 보존·복원 및 소비 경로 검증이 완료된 파일만 Git 추적에서 제외하며, 로컬 검수 원본과 기존 게스트·찜·기록을 보존한다. 실패한 이관은 재개 가능해야 하고, 내용 변경은 기존 승인 재사용으로 처리하지 않는다.

#### Scenario: 기존 승인 이미지의 위치만 변경

- **WHEN** 승인된 원본과 동일한 바이트를 Storage로 이관하고 다운로드한 파일의 해시가 일치한다
- **THEN** 기존 놀이 ID·원본 이미지 해시·승인 이력을 유지하고 위치 변경만으로 재승인을 요구하지 않는다.

#### Scenario: 누락 또는 부분 업로드

- **WHEN** 업로드·다운로드·접근 권한·해시 검사 중 하나라도 실패한다
- **THEN** 해당 이미지의 새 참조 활성화와 Git 추적 제외를 중단하고 로컬 원본·기존 정상 참조·완료된 업로드 결과를 보존한다.

#### Scenario: 승인 이후 이미지 변경

- **WHEN** Storage의 이미지 바이트가 승인된 원본 또는 매니페스트 해시와 달라진다
- **THEN** 검증에 실패하고 새 이미지의 공개 반영을 막으며 변경된 이미지의 재검수를 요구한다.

#### Scenario: 새 checkout에서 검수 재개

- **WHEN** 관리자가 Git에 이미지가 없는 작업 환경에서 기존 검수 항목을 연다
- **THEN** 권한이 있는 복원 절차로 원본을 내려받아 해시 확인 후 검수하며, 실패 시 완료·승인 상태를 바꾸지 않고 누락을 알린다.

#### Scenario: 콘텐츠 비공개 전환

- **WHEN** 기존 공개 놀이가 비공개 또는 이미지 검토 상태로 전환된다
- **THEN** 현재 앱·공유 메타데이터에서 해당 이미지 참조를 제거하고 다음 공개 정리 대상에 포함한다. 이미 내려받은 사본과 브라우저 캐시의 회수까지 보장하지 않는다.
