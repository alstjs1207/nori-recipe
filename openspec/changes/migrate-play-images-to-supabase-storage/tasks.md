## 1. Storage와 버전 매니페스트

- [ ] 1.1 대상 계정/조직의 한도·파일 총량·프로젝트·환경·버킷을 확정하고 원본 비공개/서비스 자산 공개 정책을 구성한다. 관리자·비인가 요청으로 조회/쓰기/삭제 허용 여부를 확인하고 비밀을 제외한 설정·결과를 기록한다.
- [ ] 1.2 ID별 원본/상세/썸네일 체크섬과 버전 경로를 기록하는 매니페스트·이관 도구를 구현한다. dry-run, 누락·손상·부분 성공 재개·다른 원본 덮어쓰기 방지·동일 파일 재실행 fixture로 검증하고 명령/관리 환경변수를 DEVELOPMENT.md에 문서화한다.
- [ ] 1.3 원본 업로드·다운로드 복원 검증과 승인된 live 이미지의 파생 업로드를 구현한다. draft/archived/review의 공개 게시 차단, 기존 승인 해시 보존, 변경 시 재검수, 비공개 전환 정리 대상 생성 회귀로 검증하고 CON-004·CON-005의 실제 소스·테스트 근거를 기록한다.

## 2. 웹·공유·PWA 연결

- [ ] 2.1 웹 이미지와 공유 HTML이 동일 매니페스트의 공개 상세/썸네일 URL을 사용하도록 연결한다. 버전 교체·기본 이미지·잘못된 ID·비공개 이미지 제외·Preview/Production의 canonical 및 OG URL을 이미지 단위/웹 회귀로 검증하고 빌드 설정을 문서화한다.
- [ ] 2.2 허용된 Storage origin/공개 버킷의 CORS 이미지 캐시와 실패 기본 표시를 구현한다. 방문 후 오프라인·미방문 실패·404/5xx·opaque 응답·무관한 origin 제외·80개 상한·선택 업데이트를 웹 오프라인 회귀로 검증하고 WEB-002 보존 근거를 남긴다.
- [ ] 2.3 비공개 원본과 관리자 자격 증명 없이 공개 자산으로 웹 배포용 빌드를 재현한다. 새 checkout/fixture에서 필수 자산 누락·잘못된 해시의 빌드 중단과 기존 배포 보존을 확인하고 CI/Vercel 및 로컬 검증 경계를 문서화한다.

## 3. 네이티브와 로컬 검수 호환

- [ ] 3.1 네이티브 빌드 전에 공개 서비스용 이미지를 해시 검증해 생성 경로에 준비하고 정적 참조를 연결한다. 원본 JPEG가 없는 환경의 Expo export와 첫 오프라인 이미지 표시·검토 중 기본 표시를 검증하고 준비/캐시 복원 절차를 문서화한다.
- [ ] 3.2 관리자 원본 복원을 기존 이미지 준비·생성·로컬 검수 흐름에 연결한다. 기존 승인 유지·바이트 변경 승인 무효화·복원 실패 시 원본/완료 결과 보존을 검수 회귀로 검증하고 로컬 관리 도구 안내를 갱신한다.

## 4. 실제 이관과 Git 추적 전환

- [ ] 4.1 대상 놀이 이미지의 비공개 원본 보존·다운로드 해시·공개 파생 자산을 실제 환경에서 검증한다. ID별 결과와 부분 실패를 비밀 없는 보고서에 남기며 웹/PWA·공유 봇·네이티브 검증이 끝날 때까지 기존 참조와 로컬 파일을 유지한다.
- [ ] 4.2 검증된 대상만 로컬 원본을 유지하며 Git 추적에서 제외하고 생성 이미지/캐시를 ignore한다. 새 checkout의 원본 복원·웹/네이티브 빌드와 마지막 정상 매니페스트/객체 버전 롤백을 확인한다. 다른 이미지 파일·과거 Git 이력은 변경하지 않는다.
- [ ] 4.3 실제 구현에 맞춰 현재 명세·policy-map·source-index·DEVELOPMENT.md 및 자산 제공처 고지를 갱신한다. `pnpm spec:index`, `pnpm spec:check`로 근거 연결을 확인하고 놀이 JSON·로컬 데이터·GA4 정책이 유지되는지 관련 회귀로 검증한다.
