## 첫 오프라인 브라우저 검증

Node24.22.2/pnpm10.33.0을 사용했다. 실제 공개416개를 익명으로 해시 검증해 로컬 공개 자산 캐시를 준비하고, 관리자 키/놀이 JPEG가 없는 희소 소스에서 Expo web export를 재현했다. 빌드의 로컬 캐시는 클라이언트의 전체 이미지 선저장 기능이 아니다. 실제 워커는 기존13개 셸 자산만 준비하며 미디어80개를 유지한다.

1. 사용자의 기존 사이트 저장소를 초기화하지 않고 새 origin `http://127.0.0.1:62397`에서 `/settings`만 온라인으로 열었다. 기본 화면 준비 완료와 새 셸 캐시를 확인했다. 홈 화면은 온라인으로 방문하지 않았다.
2. 이 검사에서 띄운 전용 서버를 실제 종료하고 HTTP health가 응답하지 않는 것을 확인했다. ego 페이지를 브라우저 offline으로 설정했다.
3. 처음 `/`를 열어 환영 기본 화면·생년월 안내·오프라인 안내·기본 아이콘을 확인했다. `/settings`도 열렸고 기본 화면 준비 완료가 유지됐다.
4. 서버가 중단된 상태에서 기록 보관·놀이 안전 이용 안내를 실제 펼쳐 내용이 보이는 것을 확인했다. 사용자 입력·저장·초기화·분석 동의를 바꾸지 않았다.
5. 검사 후 페이지 네트워크 설정과 서버를 복구하고 사용자 확인용 결과 탭을 유지했다. 기존 사용자 origin의 저장소는 열어 지우거나 수정하지 않았다.

브라우저의 페이지 offline 에뮬레이션은 서비스 워커의 외부 이미지 요청까지 모두 차단하지 않았다(대표 썸네일 하나가 로드됨). 따라서 이 결과를 전체 이미지 오프라인 또는 실제 기기 비행기 모드 검증으로 보고하지 않는다. 요구한 기본 화면의 HTML/JS/CSS/기본 아이콘은 실제로 중단된 로컬 서버 대신 셸 캐시에서 열렸으며, 네트워크 전체 실패의 미방문 이미지 기본 표시/80개 경계는 별도 워커 회귀로 확인했다. 최초 온라인 준비 전·브라우저의 캐시 삭제 후·실기기 홈 화면 설치는 이번 보장 범위가 아니다.
