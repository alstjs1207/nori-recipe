# 최근 본 놀이 — 작업 예정·미착수

계획 문서만 등록했다. 아래 체크박스는 실제 구현·검증 후에만 완료한다. 제안 계약은 CAT-005·LOC-003이며 CAT-001·CAT-004·LOC-001·LOC-002·PRI-001·PRI-002를 보존한다.

## 1. 열람 저장과 기존 데이터 보존

- [ ] 1.1 게스트별 열람 모델과 최신 20개 upsert/조회/비우기를 웹·네이티브 저장에 구현한다. 재열람 중복 제거·정렬·상한·다른 게스트 분리 fixture 회귀로 검증한다.
- [ ] 1.2 기존 DB 및 웹 저장의 추가 이관과 실패 복구를 구현한다. 기존 찜·완료 로그·guestId·tombstone 보존, 손상값·쓰기 실패·동시 쓰기 fixture로 검증한다. 찜 분류 change와 migration 적용 순서도 기록한다.
- [ ] 1.3 활동/전체 초기화에 열람 목록 정리를 연결하고 LOC-003과 policy-map 근거를 실제 소스·테스트로 갱신한다. 초기화 후 재실행·다른 게스트 보존 회귀 및 `pnpm spec:check`로 검증한다.

## 2. 상세 진입과 최근 본 화면

- [ ] 2.1 웹·네이티브에서 공개 상세 활성화 후에만 열람을 저장한다. 프리렌더·카드 노출·잘못된 ID·중복 focus·저장 실패가 완료/찜/상세 이용에 영향을 주지 않는 회귀로 검증한다.
- [ ] 2.2 탐색 화면에 최근 본 영역·상세 재진입·목록 비우기·빈 상태·실패 안내를 구현한다. 키보드/터치 탐색, 재방문, 삭제·비공개 콘텐츠 제외를 화면 시나리오로 검증한다.
- [ ] 2.3 CAT-005·공통 로컬 저장 안내·policy-map·필요한 source-index를 실제 구현과 함께 갱신한다. 신규 분석 전송이 없고 기존 검색·완료 로그 의미가 유지되는지 소스 검토와 관련 회귀·`pnpm spec:check`로 검증한다.

## 3. 통합 검증

- [ ] 3.1 Node 24/pnpm 10.33.0에서 `pnpm verify:local`을 실행하고 명령·날짜·성공/실패와 재현 가능한 fixture 결과를 이 change에 기록한다.
- [ ] 3.2 웹 로컬/Preview와 네이티브 검증 환경에서 열람→재열람→재실행→비우기→초기화 전체 흐름을 확인하고 실제 환경·미확인 범위를 기록한다. 실제 사용자 저장소를 초기화하지 않는다.
