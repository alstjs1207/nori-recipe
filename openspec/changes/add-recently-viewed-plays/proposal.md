# 최근 본 놀이

## Why

찜하지 않고 닫은 놀이를 다시 찾으려면 검색을 반복해야 한다. 완료 기록과 별개인 최근 열람 목록을 제공해 놀이를 쉽게 다시 꺼내 보도록 한다.

## What Changes

- 상태: **작업 예정·미착수**. 사용자는 기능별 OpenSpec 계획 등록을 요청했으며 이번 작업은 구현을 포함하지 않는다.
- 공개 놀이 상세를 실제로 연 경우에만 최근 본 목록을 로컬에 저장한다.
- 동일 놀이 중복 제거, 최근 순 정렬, 목록 비우기, 빈 상태와 저장 실패 처리를 추가한다.
- 제안 기본값은 게스트별 최근 20개이며, 웹·네이티브 모두 제공한다. 이 수치와 노출 위치는 구현 전 설계 검토 대상이다.
- 열람을 완료·찜·추천 피드백으로 취급하지 않으며 신규 분석 전송은 추가하지 않는다.

## Capabilities

### New Capabilities

없음. 기존 카탈로그와 로컬 데이터 영역을 확장한다.

### Modified Capabilities

- `catalog`: CAT-001·CAT-004를 보존하고 CAT-005 최근 본 목록·재열람 계약을 추가한다.
- `local-data`: LOC-001·LOC-002를 보존하고 LOC-003 열람 목록의 보관·초기화 계약을 추가한다.

## Impact

- 예상 구현: `app/(main)/play/[id].tsx`, `app/(main)/play/[id].web.tsx`, 탐색 화면, `src/db/queries.ts`, `src/db/schema.ts`, 세션 초기화.
- SQLite/AsyncStorage에서 기존 guestId·찜·완료 로그·tombstone을 유지한다. PRI-001·PRI-002의 분석 동의·허용 목록 정책도 유지한다.
- 백엔드·계정·동기화 의존성 없이 진행한다. 현재 specs와 policy-map의 구현 완료 근거는 이번 계획 등록에서 변경하지 않는다.
