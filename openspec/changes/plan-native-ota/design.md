# 네이티브 업데이트 채널 계획 설계 전 확인

## Context

과거 공통 OTA 계획은 의존성 설치 외에 연결되지 않았다. app.json에 update URL/runtimeVersion이 없고 eas.json·checkUpdate 유틸이 없다. WEB-002의 서비스 워커와 구분한다.

## Goals / Non-Goals

목표는 기존 계획과 현재 코드를 분리해 미완료 과제를 추적하는 것이다. 이번 문서 작성은 서비스 기능 구현이나 정책 확정이 아니다.

## Decisions

- 원본 로컬 데이터·기존 추천·검수 승인 해시 호환을 우선 보존한다.
- 정책 결정 뒤 실제 구현 범위와 delta를 다시 정리한다.
- 현재 specs에 미구현 기능을 합치지 않는다.

## Risks / Trade-offs

과거 계획의 표현·일정·가격 또는 의존성만으로 완료를 오인할 수 있다. 소스·실행 증거와 명시적 결정으로 해소한다.

## Migration Plan

후속 구현 전에 기존 데이터의 이관·실패 복구·롤백을 설계한다. 현재는 이관하지 않는다.

## Open Questions

- EAS 프로젝트·채널 소유권·runtimeVersion·스토어 배포 상태를 확인한다.
- 다음 시작 적용·실패 복구·캐시·롤백 정책을 결정한다.
