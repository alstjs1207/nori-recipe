# Design — 확정 정책과 최종 홈·기록 시안

## Context

현재 회차 저장 객체는 회차 ID·게스트·추천 ID·실제 완료 기록 참조를 보관한다. 재료 저장 경로가 매번 restart를 호출해 부분 완료도0/3으로 바뀐다. 사용자가 이 전환을 변경하기로 확정했다.

## Goals / Non-Goals

- 목표: 홈의 재료 변경에서 완료 칸과 도장을 보존하며 미완료 칸만 새 조건으로 추천한다.
- 목표: 완료0/1/2개에서는 진행을 이어가고, 완료3개 이후의 명시적 재료 저장에서만 다음 회차로 넘어간다.
- 2026-11-21 최종 시안을 구현한다. 탐색 탭 재설계·카드별 수동 교체·평가와 완료 분리·과거 이력 배지·새 분석 이벤트는 포함하지 않는다.

## Decisions

| 변경 직전 상태 | 재료 저장 후 추천 | 진행 |
| --- | --- | --- |
| 0/3 | 현재 조건으로3개 전체 재추천 | 0/3 |
| 1/3 | 완료한1개 고정 + 미완료2개 재추천 | 1/3 |
| 2/3 | 완료한2개 고정 + 미완료1개 재추천 | 2/3 |
| 3/3 | 다음 회차의3개 전체 재추천, 도장 초기화 | 0/3 |

- 구현 방향은 완료 전에는 기존 회차 ID와 완료 기록 참조를 유지하고, 미완료 추천 ID·재료 문맥만 갱신하는 것이다. 전체 완료 후 다음 추천에서 새 회차 ID를 만든다.
- 완료 칸은 이미 수행한 놀이이므로 새 재료 조건에 맞지 않는다는 이유로 지우지 않는다. 남은 칸은 완료 ID를 제외한 후보에 기존 월령·게시 상태·제외 재료·재료 우선·보호자 준비 확인 규칙을 적용한다.
- 조건에 맞는 대안이 부족하면 적격한 미완료 카드를 유지할 수 있다. 순서만 바꿔 새 놀이가 생겼다고 표시하지 않으며, 안전 필터를 해제해 빈 칸을 채우지 않는다.0~2개 적격 후보의 기존 GAP-001은 별도 잔여 범위다.
- 예: A/B 완료·C 미완료에서 재료를 바꿔 D가 추천되면 A✓/B✓/D와2/3을 표시한다. D를 완료하면3/3·콘페티 한 번이고, 재진입·날짜 변경·중복 기록으로 다시 축하하지 않는다.
- 미완료 카드 교체 자체는 완료 저장이 아니므로 콘페티/완료 광고를 발생시키지 않는다. TOSS-007의 마지막 미완료 저장 판정은 유지된 회차의 실제 완료 기록으로 수행해야 한다.
- 누적 기록은 모든 회차의 실제 놀이 기록을 보존한다. 회차 진행은 현재 추천 묶음만 관리하며 과거 묶음의 미완료 진행을 별도 목록으로 쌓지 않는다.

## Risks / Trade-offs

- 같은 회차 ID에서 연속 재료 저장이 발생하므로 회차 ID 외에 문맥/요청 순서도 확인해 오래된 결과가 최신 추천을 덮지 않게 해야 한다.
- 재료·새 후보·유지된 완료 참조는 저장 성공 후 함께 반영해야 한다. 실패/취소에는 기존 추천·진행·재료를 보존하고 재시도 경로를 제공한다.
- ‘오늘’과 ‘이번 추천’, 재료 저장과 진행 유지/새 회차 시작의 표현을 구현 시점에 실제 동작에 맞춘다. 홈은 작은 ‘이번 놀이 도전’·0/3~3/3 진행과 대표1개/하단2개 구성을 유지한다.

## Migration Plan

1. 기존0/3·1/3·2/3·3/3 회차 저장을 그대로 읽고 날짜/업데이트만으로 초기화하지 않는다.
2. 기존 누적 기록·기기/게스트 분리·삭제 표시·찜·프로필을 보존한다. 이전 기록을 새 회차의 완료로 재수입하지 않는다.
3. 영구 저장 실패·기록 쓰기 실패·중간 종료·재실행·겹치는 재료 요청을 fixture와 실제 화면에서 검증한 후 현재 명세를 동기화한다.

## Open Questions / Boundaries

0/1/2/3 완료 상태의 재료 변경 정책은 사용자 합의가 끝났다. 재승인이 필요한 미확정 사항으로 취급하지 않는다. 이번 결정은 홈의 재료 편집에 한정하며, 자동 월령/콘텐츠 삭제·부적격 복구와 별도의 프로필/제외 재료 편집은 기존 안전 규칙을 적용하고 구현 때 영향·회귀를 대조한다. 실제 네이티브/토스 실기기와 안전 후보0~2개 경계는 기존 후속 문서에서 계속 추적한다.

## 완료 묶음과 기록 화면

- 회차와 함께 최종 추천 ID/완료 참조의 묶음 후보를 저장한다. 세 활동 행이 실제 활성 상태인 경우만 달성으로 조회한다. 세 번째 쓰기 실패·중간 종료는 빈 묶음을 만들지 않고, 재시도·중복 기록은 같은 회차의 한 묶음으로 유지한다.
- 완료한 날짜는 실제 세 번째 완료 시간이며 조회 기기 시간대로 표시한다. A/B 완료 후 C→D 교체면 묶음은 A/B/D다. 다음 추천은 누적 묶음/개별 기록을 지우지 않는다. guest와 활동 삭제 표시를 대조한다.
- 기존 v1 저장 키와 회차를 읽고 선택 재료·보호자 확인·revision·묶음 후보를 선택 필드로 확장한다. 재료 편집은 실제 완료 참조를 확인하고 새 추천·문맥을 단일 JSON에 원자 저장한다. 레거시 재료 키는 최초 fallback이며 새 문맥이 우선한다. 같은 회차의 오래된 자동 pin은 revision으로 거부한다.
- 기본 ‘완성한 묶음’은 최근3묶음, ‘개별 놀이’는8개씩 표시한다. 묶음 전체 보기는 월 선택으로 과거 기록을 조회한다. 날짜는 크게,3개 사진 아래 제목은 바로 표시하고 반복 완료 문구는 제거한다.
- 공통 상단은 전체 누적 기록의 놀이 횟수·날짜 수·경험한 영역 수와 ‘이런 놀이를 함께했어요’7개 영역을 표시한다. 영역 패널은 접을 수 있고 영역별 놀이 탐색 링크를 유지한다. 이는 발달 진단이 아니다.
- 웹/PWA/토스는 같은 웹 화면을 사용한다. 네이티브 기록 탭에도 같은 조회/묶음/기간 구성을 연결하며 타입 검사와 실제 기기 확인을 구분한다.
