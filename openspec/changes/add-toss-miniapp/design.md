# Design

## Context

Expo 54/React 19/Metro 단일 웹 앱이며 웹은 AsyncStorage의 localStorage 구현, 네이티브는 SQLite를 쓴다. 기존 이미지 등록 작업이 미커밋 상태이므로 관련 파일을 덮어쓰지 않는다. 토스 SDK 3.10.0의 공개 API/타입과 2026-11-17 공식 문서를 기준으로 한다.

## Goals / Non-Goals

**Goals:** 기존 핵심 화면을 토스 도메인의 정적 번들에서 실행하고 웹과 독립적으로 검증한다.

**Non-Goals:** 토스 로그인·서버 백업·결제·광고·웹 기록의 자동 이전·콘솔 계정 생성·공개 출시.

## Decisions

- Metro가 토스 빌드에서만 `runtime.toss.ts`를 선택한다. 일반 웹은 SDK를 로드하지 않고 원래 저장 구현을 쓴다. 공통 스토어의 데이터 형식/키/guestId 생성 규칙은 유지한다.
- 토스는 식별키를 받은 뒤에만 시작한다. SDK Storage의 키를 사용자별로 분리하고 실패하면 메모리/localStorage로 대체하지 않는다. 계정 변경은 기존 스토어를 새 사용자 공간에 쓰지 않도록 차단하고 재시작한다. 초기화는 현재 사용자 공간의 서비스 키만 제거한다.
- 기존 React 19를 유지한다. 현재 TDS 2.5.1 peer 범위가 React 18까지이므로 자체 UI와 공식 플로팅 탭바 규격을 사용한다. 토스 내비게이션과 중복되는 뒤로가기·웹 헤더, PWA 설치/서비스 워커 업데이트, 웹 분석 안내를 토스 화면에서 제외한다.
- 뒤로가기는 열린 다이얼로그 닫기→앱 내부 이전 화면→홈→최초 화면 종료 순서다. SDK SafeArea의 변경을 반영하고 구독을 해제한다.
- 공유는 공개 놀이 ID만 `intoss://<appName>/play/<id>`에 담는다. 임시 테스트 스킴·개인 입력·재료 query를 공유하지 않는다. 실패하면 안내하고 재시도하며 자사 웹으로 우회하지 않는다.
- 동일 승인 이미지 준비/공개 무결성 도구를 사용하되 `dist-toss`로 별도 export한다. 토스 HTML에는 PWA 등록/웹 canonical·OG·소개 페이지를 포함하지 않는다. SDK CLI로 `.ait`를 만들고 100MB 제한·기밀/소스맵·불필요한 파일 포함을 검사한다. 웹 `dist`는 건드리지 않는다.
- 첫 화면에 AI 삽화 사용을 알리고 실제 삽화에도 라벨을 표시한다. 토스의 개인정보 안내는 기기 저장·식별키·Supabase 공개 이미지 요청과 공유를 구분한다. GA 전송은 토스에서 명시적으로 비활성화한다.

## Risks / Trade-offs

- 실 SDK 브릿지는 일반 브라우저에서 제공되지 않는다 → 실제 SDK 번들 생성과 브릿지 fixture UI 검증을 구분하고 콘솔 QR 실기기 확인을 출시 체크리스트에 남긴다.
- appName은 콘솔 등록 값과 같아야 한다 → 기본 `nori-recipe`, 환경변수로 설정하며 콘솔 일치 여부를 별도 확인한다.
- 기기 저장은 백업이 아니다 → 웹/토스/다른 기기의 데이터가 자동으로 공유되지 않음을 고지한다.
- 토스 업로드·심사·실제 공유 앱은 계정/기기가 필요하다 → 로컬 검증을 통과한 산출물을 만들고 실제 수행한 범위만 보고한다.
