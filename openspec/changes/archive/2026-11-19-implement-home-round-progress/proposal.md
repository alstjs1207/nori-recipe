# Proposal

## Why

사용자가 도장을 이번 추천3개의 진행 상태로 정의하고 날짜가 바뀌어도 부분 완료를 유지하며, 명시적 새 추천이면 같은 놀이도0/3부터 시작하는 정책을 승인했다. 기존 구현은 누적 이력 전체로 도장을 표시하고 반복 놀이의 새 완료를 구분하지 못했다. REC-004·GAP-002의 다음 회차 시점과 완료 기준을 이번 요청 범위에서 확정한다.

## What Changes

- REC-004: guest별 영구 회차 ID·고정 추천·해당 회차의 기록 참조를 저장한다. 날짜/일반 재진입/전체 완료만으로 바꾸지 않으며 명시적 새 추천은 같은 재료·놀이 ID도0/3으로 시작한다. 과거 라벨은 추가하지 않는다. 자동 월령·콘텐츠 변경은 부적격 항목만 보충한다.
- LOC-001/002·LOG-001: 기존 게스트·프로필·찜·누적 기록·SQLite v3는 보존한다. 기존 고정 추천의 활성 기록은 최초 회차로 한 번 호환 이전한다. 회차 참조를 기록 쓰기 전에 저장하고 실제 DB 기록과 대조해 중단/실패 시 유령 완료를 방지한다. 저장 실패는 영구/메모리 회차를 보존하고 직렬 큐·회차 ID로 오래된 요청을 거부한다. 활동/전체 초기화도 회차에 적용한다.
- TOSS-007: 광고의 마지막 미완료 판정도 같은 회차 기록으로 맞추며 SDK·그룹 ID·비전송 정책은 유지한다.
- GOV-002: 새 homeRecommendation store와 회귀 파일을 recommendations/local-data에 명시적으로 분류한다.
- ONB-001/002, REC-001/002/003/005, LOG-002/003, PRI-001/002/003/004, WEB-002/005/006 및 TOSS-001/002/003의 안전·재료 우선·준비 확인·개인화·누적 통계·분석·탐색·저장 범위는 유지한다. 조건부 안내의 작은 글씨와 단발 폭죽 수정도 보존한다. 후보가0~2개인 안전 경계 GAP-001과 실제 네이티브/토스 검증은 별개다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `recommendations`: 추천 회차별 진행·새 추천·기존 데이터 호환.
- `local-data`: 회차의 원자적 객체 저장·직렬화·초기화.
- `play-records`: 누적 기록과 회차 완료 집계의 분리.
- `toss-miniapp`: 회차별 완료 광고 판정.
