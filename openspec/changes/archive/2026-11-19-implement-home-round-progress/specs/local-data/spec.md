## MODIFIED Requirements

### Requirement: LOC-001 플랫폼별 로컬 저장과 동기화 메타데이터

서비스 MUST 네이티브 사용자 데이터를 SQLite, 웹 사용자 데이터를 AsyncStorage에 저장하고 놀이 콘텐츠는 번들에서 읽는다. DB 버전 3의 updated_at·deleted_at·sync_state는 향후 동기화 대비 메타데이터이며 서버 동기화가 아니다. 웹 번들에 SQLite/WASM을 넣지 않는다. 추천 회차는 플랫폼의 세션 저장소에 guestId·회차 ID·추천 ID·완료 기록 참조를 하나의 버전1 객체로 보관하며 기존 DB 스키마·놀이 기록을 바꾸지 않는다.

#### Scenario: 웹 저장

- **WHEN** 웹이 기록 저장소를 사용한다
- **THEN** 브라우저 저장소를 사용한다.

#### Scenario: 기존 DB

- **WHEN** 네이티브의 낮은 스키마 버전을 연다
- **THEN** 순차 마이그레이션하며 기존 시간을 백필한다.

#### Scenario: 회차 저장과 실패 복구

- **WHEN** 추천 회차 또는 그 회차의 완료 기록 연결을 저장한다
- **THEN** 영구 저장 성공 후 메모리 상태를 바꾸고 직렬 큐·회차 ID로 오래된 저장 요청을 거부한다. 완료 연결은 활동 DB 쓰기 전에 보관하되 실제 활성 DB 기록이 있어야 완료로 계산한다. 저장 실패·중간 종료가 기록을 소실시키거나 유령 도장을 만들지 않는다.

### Requirement: LOC-002 활동 초기화와 전체 삭제 구분

서비스 MUST 활동 초기화는 활성 로그·발달 로그·찜에 삭제 표시를 남기는 방식으로 수행하고 전체 로컬 데이터 초기화는 해당 게스트 사용자 데이터를 물리 삭제하고 프로필·추천·동의를 초기화한 뒤 새 guestId를 만든다. 브라우저 저장소 삭제로 소실된 기록의 계정 복원은 제공하지 않는다.

#### Scenario: 활동 초기화

- **WHEN** 기록 초기화를 선택한다
- **THEN** 삭제 표시 후 활성 조회에서 제외하고 추천 회차를 새로 시작한다.

#### Scenario: 전체 초기화

- **WHEN** 전체 로컬 데이터 초기화를 선택한다
- **THEN** 사용자 데이터와 세션 설정·동의를 지우고 새 게스트·빈 추천 회차로 시작한다.
