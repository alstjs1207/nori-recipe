## ADDED Requirements

### Requirement: CON-001 마스터와 게시 안전 검증

콘텐츠 MUST 0~48개월·7개 발달영역·표준 slug·개별 출처와 유효 상태를 사용하고 substitutes 배열은 비워 둔다. live에는 reviewPending 재료, 생밀가루·생반죽 직접 놀이, 36개월 미만의 작은 구슬·비즈·폼폼·워터비즈·플레이콘·일반 슬라임을 허용하지 않는다. 이 목록은 코드의 게시 규칙이며 외부 안전 기준 전체를 대신하지 않는다.

#### Scenario: 검증 실패

- **WHEN** 미승인 재료 또는 금지 게시 조건이 있다
- **THEN** 게시 콘텐츠 검증에서 오류를 반환한다.

#### Scenario: 이력 보존

- **WHEN** 제외 놀이가 archived 상태로 남아 있다
- **THEN** 게시 금지를 유지하면서 이력은 보존할 수 있다.

### Requirement: CON-002 초안부터 이미지 준비까지

수집 파이프라인 SHALL 원문→정규화→실제 ID의 draft→놀이 및 없는 새 재료의 실제 이미지 생성·저장→배치→검수 링크 순으로 준비한다. 신규 배치는 현재 내용 해시와 실제 이미지·생성 기록이 모두 준비된 경우에만 만든다. 누락·stale·손상은 초안과 완료 결과를 보존하며 부분 배치나 사용자 승인으로 꾸미지 않는다.

#### Scenario: 이미지 미완료

- **WHEN** 신규 수집 놀이의 이미지가 하나라도 미완료다
- **THEN** 신규 배치를 만들지 않는다.

#### Scenario: 재개

- **WHEN** 완료한 이미지와 같은 정규화 파일·ID가 있다
- **THEN** 준비 결과를 재사용하고 미완료만 이어서 처리한다.

### Requirement: CON-003 현재 내용에 대한 명시적 승인

게시 도구 MUST 사용자 승인된 항목만 현재 내용·재료 정의·이미지 해시·확인란과 함께 검증한 뒤 백업·반영한다. 내용이나 이미지 변경은 과거 승인을 무효화한다. 재료는 신규 추가·기존 대체·보류를 따로 결정하며 재료 승인만으로 놀이가 게시되지 않는다. JSON 가져오기·생성 완료·서버 시작은 승인이 아니다.

#### Scenario: 오래된 승인

- **WHEN** 이미지 또는 내용이 승인 이후 변경된다
- **THEN** 기존 승인을 거부하고 재검수를 요구한다.

#### Scenario: 사용자 승인

- **WHEN** 현재 놀이·재료·이미지 확인과 승인된 한 항목을 반영한다
- **THEN** 검증·백업 후 해당 항목만 live 및 이미지 매핑에 반영한다.
