## ADDED Requirements

### Requirement: WEB-005 새 진입과 복귀의 스크롤 정책

서비스 SHALL 새 링크·탭·앞으로 이동으로 연 화면은 같은 놀이/경로여도 맨 위에서 시작하고, 화면 뒤로가기·브라우저 이력 복귀·네이티브 뒤로가기로 돌아온 목록은 기존 스크롤을 복원한다. 새 상세는 기본 내용 탭, 새 기록은 초안을 유지한 폼 상단, 새 목적 검색은 해당 조건의 상단을 표시한다. 반복 방문한 화면의 이동 이력을 중복 제거하지 않아 뒤로가기가 직전 출발 목록을 건너뛰지 않게 한다. 입력·파라미터만 바뀌는 업데이트를 새 진입으로 처리하지 않는다. 설정은 상단에서 시작하되 개인정보 목적 링크는 해당 문단을 연다. 늦게 로드한 목록/이미지의 높이를 고려하며 사용자의 스크롤 조작을 복원으로 덮어쓰지 않는다. 웹/PWA/토스 공통 DOM과 네이티브 외곽 스크롤에서 같은 원칙을 적용한다.

#### Scenario: 동일 경로의 새 진입

- **WHEN** 같은 놀이·기록·탐색·설정을 링크나 탭으로 다시 연다
- **THEN** 새 진입은0에서 시작하고 같은 경로를 다시 눌러도 옛 스크롤을 복원하지 않는다.

#### Scenario: 목록 뒤로 복귀

- **WHEN** 목록에서 상세를 읽고 뒤로 돌아온다
- **THEN** 출발 목록의 조건·기존 위치를 복원한다.

#### Scenario: 개인정보 목적 이동

- **WHEN** 개인정보 목적 링크로 설정을 연다
- **THEN** 실제 화면 DOM이 준비된 후 개인정보 문단을 열어 그 위치를 표시한다.

#### Scenario: 늦은 콘텐츠와 사용자 조작

- **WHEN** 복귀 목록의 높이가 데이터/이미지 로드 후 늘어나거나 사용자가 직접 스크롤한다
- **THEN** 목표 위치 복원을 재시도하되 사용자의 조작 이후에는 강제로 되돌리지 않는다.

#### Scenario: 반복 방문의 직전 목록

- **WHEN** 홈·탐색·상세를 여러 번 오간 뒤 복합 필터를 적용한 목록에서 상세를 열고 브라우저 뒤로가기를 누른다
- **THEN** 직전 목록으로 돌아가 조건과 위치를 보존하며 과거 방문의 초기화 플래그로 입력을 지우지 않는다.
