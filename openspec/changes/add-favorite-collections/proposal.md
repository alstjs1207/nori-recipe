# 찜한 놀이 분류

## Why

현재 찜은 한 목록에 모여 있어 항목이 늘면 실제로 할 놀이를 찾기 어렵다. 사용자가 목적별 모음으로 나누어 저장한 놀이를 쉽게 꺼내 보도록 한다.

## What Changes

- 상태: **작업 예정·미착수**. 이번에는 계획만 등록한다.
- 찜 화면에 전체·미분류·사용자 모음별 탐색과 모음 생성·이름 변경·삭제를 제공한다.
- ‘이번 주 해보기’, ‘주말에 하기’, ‘다시 하기’는 모음 이름 예시이며 일정·알림·자동 이동을 뜻하지 않는다.
- 단순한 첫 버전으로 한 찜은 사용자 모음 최대 하나에 배정하는 안을 제안한다. 기존 찜은 ID·시간을 유지하고 미분류로 보존한다.
- 모음 삭제는 찜 삭제와 구분하고, 게스트 분리·찜 해제·재찜·초기화·저장 실패를 다룬다.

## Capabilities

### New Capabilities

없음. 기존 찜·로컬 데이터 영역을 확장한다.

### Modified Capabilities

- `play-records`: LOG-003의 찜 전환·활성 조회를 보존하고 LOG-004 모음 관리·분류를 추가한다.
- `local-data`: LOC-001·LOC-002를 보존하고 LOC-004 찜 분류의 저장·이관·초기화 계약을 추가한다.

## Impact

- 예상 구현: `app/(main)/favorites.tsx`, `app/(main)/favorites.web.tsx`, 찜 공통 UI, `src/db/queries.ts`, `src/db/schema.ts`, 세션 초기화.
- SQLite/AsyncStorage에서 기존 guestId·찜 고유 ID·생성일·tombstone과 완료 기록을 유지한다.
- 모음 이름·분류 ID는 외부 분석에 보내지 않고 PRI-001·PRI-002를 보존한다. 백엔드·공유 모음·다중 모음 배정·추천 점수 변경은 포함하지 않는다.
