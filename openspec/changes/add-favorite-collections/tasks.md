# 찜한 놀이 분류 — 작업 예정·미착수

계획 문서만 등록했다. 아래 구현·검증은 아직 수행하지 않았다. 제안 계약 LOG-004·LOC-004를 추가하며 LOG-003·LOC-001·LOC-002·PRI-001·PRI-002는 보존한다.

## 1. 모음과 분류 저장

- [ ] 1.1 게스트별 모음·찜의 nullable 단일 분류 모델과 웹/네이티브 저장 이관을 구현한다. 기존 활성/삭제 찜 ID·시각·tombstone·완료 로그 보존 및 게스트 분리 fixture 회귀로 검증한다. 최근 본 놀이 change와 migration 적용 순서도 기록한다.
- [ ] 1.2 모음 생성·이름 변경·삭제·찜 이동/분류 해제 API를 구현한다. 이름 공백·길이·중복·예약명, 다른 게스트 참조, 모음 삭제 시 미분류 이동·전체 개수 유지 회귀로 검증한다.
- [ ] 1.3 기존 찜 해제/재찜·활동/전체 초기화에 분류 정리를 연결한다. 저장 실패·부분 쓰기·고아 참조·동시 쓰기·재실행 fixture에서 기존 찜과 유효 관계가 유지되고 초기화 항목이 복원되지 않는지 검증한다.
- [ ] 1.4 LOC-004와 policy-map을 실제 migration·저장 소스 및 회귀 근거로 갱신한다. 기존 LOC-001/LOC-002 계약 대조와 `pnpm spec:check`로 검증한다.

## 2. 찜 화면과 모음 관리

- [ ] 2.1 웹·네이티브 찜 화면에 전체·미분류·모음 탐색과 모음 생성·이름 변경·삭제 확인을 구현한다. 기존 찜 노출·빈 모음·비공개 콘텐츠 제외·키보드/터치 동작의 화면 회귀로 검증한다.
- [ ] 2.2 찜 카드의 모음 이동/분류 해제·오류/재시도 안내를 구현하고 기존 상세·검색 찜 버튼의 빠른 저장을 유지한다. 전체 찜 수 불변·모음 삭제 후 찜 보존·재찜 시 미분류 표시를 통합 시나리오로 검증한다.
- [ ] 2.3 LOG-004·공통 저장 안내·policy-map·필요한 source-index를 갱신한다. 모음 이름/식별자가 공유 URL·분석에 포함되지 않고 기존 찜 이벤트만 유지되는지 관련 회귀 및 `pnpm spec:check`로 검증한다.

## 3. 통합 검증

- [ ] 3.1 Node 24/pnpm 10.33.0에서 `pnpm verify:local`을 실행하고 migration·모음·찜 회귀 결과를 날짜·명령과 함께 이 change에 기록한다.
- [ ] 3.2 웹 로컬/Preview와 네이티브 검증 환경에서 기존 찜 이관→분류→이동→모음 삭제→재찜→재실행→초기화를 확인하고 실제 환경·미확인 범위를 기록한다. 실제 사용자 저장소로 초기화 테스트를 하지 않는다.
