## ADDED Requirements

### Requirement: LOC-004 찜 분류의 로컬 저장과 보존

서비스 MUST 모음과 찜의 분류를 게스트별 로컬 데이터로 저장·복원하고 기존 찜 ID·생성일·삭제 표시를 보존한다. 활동 초기화 시 모음과 활성 분류도 비우고 전체 초기화 시 해당 게스트의 분류 데이터를 제거한다. 사용자 모음 이름·분류 식별자는 외부 분석에 전송하지 않는다.

#### Scenario: 기존 데이터 이관

- **WHEN** 분류 정보가 없는 기존 웹 저장 또는 낮은 네이티브 DB 버전을 연다
- **THEN** 기존 활성 찜을 미분류로 읽고 삭제 표시된 찜을 되살리지 않는다. 완료 기록·개인화 문맥·guestId는 보존한다.

#### Scenario: 게스트 분리

- **WHEN** 다른 게스트 소유의 모음으로 분류를 시도하거나 모음을 조회한다
- **THEN** 다른 게스트의 데이터를 노출·변경하거나 찜을 연결하지 않는다.

#### Scenario: 여러 변경의 저장 실패

- **WHEN** 모음 이동·모음 삭제·분류 저장 중 쓰기가 실패한다
- **THEN** 기존 찜과 유효한 분류 관계를 유지·복구하고 오류와 재시도 동선을 제공한다. 실패를 저장 성공으로 표시하지 않는다.

#### Scenario: 초기화와 재실행

- **WHEN** 활동 초기화 또는 전체 초기화 후 앱을 다시 연다
- **THEN** 비운 모음·분류가 복원되지 않는다. 활동 초기화의 기존 찜·기록 tombstone 정책과 전체 초기화의 물리 삭제 정책을 유지한다.
