# 계정과 로컬 데이터 동기화 계획 설계 전 확인

## Context

과거 plan STEP 8의 방향을 보존한다. LOC-001·LOC-002는 로컬 서비스다. sync_state는 준비 메타데이터이고 scripts/upload.ts는 placeholder다.

## Goals / Non-Goals

목표는 기존 계획과 현재 코드를 분리해 미완료 과제를 추적하는 것이다. 이번 문서 작성은 서비스 기능 구현이나 정책 확정이 아니다.

## Decisions

- 원본 로컬 데이터·기존 추천·검수 승인 해시 호환을 우선 보존한다.
- 정책 결정 뒤 실제 구현 범위와 delta를 다시 정리한다.
- 현재 specs에 미구현 기능을 합치지 않는다.

## Risks / Trade-offs

과거 계획의 표현·일정·가격 또는 의존성만으로 완료를 오인할 수 있다. 소스·실행 증거와 명시적 결정으로 해소한다.

## Migration Plan

후속 구현 전에 기존 데이터의 이관·실패 복구·롤백을 설계한다. 현재는 이관하지 않는다.

## Open Questions

- 로그인 제공자·필수 동의·이관 시점·복수 게스트/기기 충돌·탈퇴/삭제 정책을 결정한다.
- 테넌트·RLS·서버 migration·idempotency와 로컬/원격 백업·롤백을 설계한다.
