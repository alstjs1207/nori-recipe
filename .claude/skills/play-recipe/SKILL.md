# 육아 놀이 수집

원문에서 실제 준비물과 진행 방법을 확인하고 `results/`에 `meta` + `activities` 구조로 저장한다. 시작할 때 `CLAUDE.md`, `src/types/play.ts`, `data/materials.json`, 기존 `data/plays.json`을 읽어 현재 스키마와 중복을 확인한다.

이 저장소의 기본 완료 범위는 수집 원본 보존 → 재료 정규화 → `draft` 병합·ID 부여 → 놀이 대표 이미지·없는 새 재료 이미지 자동 생성·저장 → 새 검수 배치 등록 → **로컬 서버의 해당 수집 건 검수 링크 전달**이다. 사용자는 그 화면에서 의견·상태를 저장하고 승인한 항목만 로컬에 반영한다. 수집 요청만으로 승인하거나 게시하지 않는다. 조사·후보 선정·JSON 저장만 요청한 경우에는 지정한 범위에서 마친다. 검수 준비 시 [공통 서버 인계 절차](../../../tools/local-review/README.md#수집-스킬에서-검수로-넘기기)를 읽고 따른다.

## 요청 범위

### 월령과 선택 조건을 자연어로 요청하기

명시한 월령을 기준으로 다음과 같은 자연어 요청을 동일한 수집 흐름으로 처리한다. 재료·발달영역은 선택 사항이며 별도 양식을 다시 작성하게 하지 않는다.

```text
24개월, 재료: 종이컵, 집게
18개월 놀이 수집해줘
24개월, 대근육 위주로 실내에서 할 놀이
18개월, 소근육이랑 정서 놀이 찾아줘
30개월, 종이컵 활용하는 놀이 5개
18~24개월, 물놀이는 빼고
24개월, 종이컵과 물감만으로 가능한 놀이 5개
```

- `X개월`은 수집의 기준 월령이다. 그 숫자와 정확히 일치하는 검색어·연령 표시에 한정하지 않고 주변 월령과 발달단계의 활동까지 범위로 탐색한다. 수집 범위는 활동의 동작·규칙·재료 조건과 원문 대상에 맞춰 정하고 근거를 남긴다. 모든 월령에 일률적인 ±N개월을 적용하지 않으며, 놀이별 실제 `ageMin/ageMax`도 X 또는 수집 범위로 일괄 덮어쓰지 않는다. 사용자가 `18~24개월`처럼 범위를 지정하면 그 범위를 우선한다. 앱 범위 밖의 요청은 0~48개월로 몰래 바꾸지 말고 요청 범위를 확인한다.
- 플랫폼을 지정하지 않으면 Instagram을 기본으로 한다. 국내·해외, 발달영역은 제한하지 않으며 적합한 활동을 고른다. 지정한 플랫폼·지역·영역·수량이 있으면 그 조건을 우선한다.
- 재료 목록은 기본적으로 그중 하나 이상을 활용하는 놀이를 찾는 조건이다. 모든 재료를 한 놀이에 억지로 넣지 않는다. `이 재료만`·`추가 재료 없이`라고 요청하면 실제 필수 준비물이 그 범위 안에 있는 활동만 선택한다. 추가 필수 재료를 선택 재료로 숨기지 않는다.
- 재료를 생략하면 재료 제한 없이 찾고 가정에서 구하기 쉬운 재료를 우선한다. 발달영역만 추가한 요청에도 재료 입력을 요구하지 않는다. 수량을 생략하면 확인 가능한 고유 활동 10개를 목표로 하되, 실제 확인한 수만 보고한다.
- `대근육`·`몸을 크게 움직이는`은 `gross_motor`, `소근육`·`손으로 조작하는`은 `fine_motor`, `인지`는 `cognitive`, `언어`는 `language`, `정서`·`감정 표현`은 `emotional`, `사회성`·`함께 어울리는`은 `social`, `감각`·`촉감`은 `sensory`를 검토 조건으로 해석한다. 실제 놀이 동작을 확인해 해당 영역을 부여하며 효과를 보장하는 문구로 바꾸지 않는다.
- `대근육 위주`는 우선순위, `소근육이랑 정서`는 두 영역을 포괄하는 수집 요청으로 해석한다. 모든 놀이에 두 영역을 억지로 부여하지 않으며 `두 영역을 함께`처럼 명시한 조건이 있으면 이를 따른다. 실내·야외·준비가 간단한·특정 재료 제외 등의 자연어 조건도 수집에 반영하고, 빠진 선택 조건을 채우도록 반복 질문하지 않는다.
- 재료 정보는 `data/materials.json`의 표시명·slug와 대조한다. 기존 재료를 재사용하고, 새 재료는 의미를 보존해 임시 정의·`reviewPending`과 재료 제안으로 준비한다. 종이컵·투명 컵처럼 기능이 다른 재료를 일반 컵으로 합치지 않는다.
- 원래 자연어 요청은 `meta.query.originalRequest`에 보존한다. 단일 기준 월령은 `meta.query.requestedAgeMonths`에, 실제 수집 범위는 `meta.query.ageMin/ageMax`에, 범위를 정한 근거는 `meta.query.ageRangeBasis`에 기록해 서로 구분한다. 명시한 범위는 `requestedAgeRange`로 보존한다. 원래 입력한 재료는 `requestedMaterials` 배열, 재료 조건은 `materialConstraint`의 `prefer` 또는 `only`로 기록한다. 재료가 없으면 빈 배열과 `prefer`를 사용한다. 요청한 발달영역은 `areas`에 기록하고 부가 조건·제외 조건도 보존한다. 이는 수집 메타데이터이며 앱 놀이 객체에는 복사하지 않는다.

### 추가 조건과 범위

- `/play-recipe 19개월 소근육`처럼 월령·영역을 받거나 자연어로 재료, 지역, 플랫폼, 수량, 후보 파일을 받을 수 있다.
- 사용자가 선정한 후보를 지정하면 그 목록을 입력으로 사용한다. 월령·영역을 다시 묻거나 다른 플랫폼의 활동을 채워 넣지 않는다.
- 앱의 월령 범위는 0–48개월이다. 숫자 월령이 없으면 도구 사용 단계와 맥락으로 편집 대상 범위를 정하고 근거를 `meta.query`에 기록한다. 범위를 합리적으로 정할 수 없을 때만 질문한다.
- 원문의 연령과 편집 대상 연령을 구분한다. 원문에 없는 연령을 출처의 권장 연령으로 쓰지 않는다. 연령 숫자만으로 도구·작은 부품의 적합성을 판단하지 않는다.
- 지정 수량을 우선한다. 수량이 없으면 고유한 활동 10개를 목표로 하되, 원문을 확인할 수 없는 활동으로 수량을 채우지 않는다.
- 발달영역: `fine_motor`, `gross_motor`, `cognitive`, `language`, `emotional`, `social`, `sensory`. 여러 영역을 함께 수집할 수 있다.

## 원문 조사

사용자가 지정한 플랫폼과 국내/해외 조건을 우선한다. Instagram만 요청했으면 YouTube·네이버 검색은 필수가 아니다.

### Instagram / Aside

1. Aside의 열린 탭을 확인하고 해당 Instagram 탭이 있으면 재사용한다. 없으면 조사 탭을 만든다. 도구가 제공한 API 문서를 따른다.
2. 계정·개별 게시물/릴스를 찾는다. Instagram 검색 결과가 부족하면 브라우저 검색엔진에서 `site:instagram.com/reel preschool scissor activity`처럼 해외 언어와 재료·놀이 동작을 조합한다. 검색 결과는 발견용이며 출처가 아니다.
3. 개별 `/p/{shortcode}/` 또는 `/reel/{shortcode}/`를 열어 계정, 캡션, 사진·영상의 재료와 방법을 확인한다. 검색 스니펫만으로 등록 가능한 원문이라고 판단하지 않는다.
4. 시각 확인은 스크린샷 또는 영상 프레임으로 한다. 캡션 확인과 시각 확인을 별도로 기록한다. 보지 못한 단계·재료는 추측을 원문 사실로 바꾸지 않는다.
5. 광고·공구·상품 소개만 있는 콘텐츠, 제외 계정 `@zzu_ni`는 건너뛴다. 접근이 막히면 확인하지 못한 부분을 기록하고 보류한다.
6. 출처는 확인한 개별 URL과 계정명으로 기록한다. 좋아요·팔로우·댓글·메시지 등의 외부 작업은 조사에 포함되지 않는다. 직접 만든 조사 탭은 마치면 닫는다.

### 다른 플랫폼

- YouTube는 개별 영상 URL과 실제 영상/설명을 확인한다. 검색·채널 목록 URL을 영상 출처로 저장하지 않는다. API를 사용하면 키 존재 여부만 확인하고 `.env` 전체나 키를 출력하지 않는다.
- 블로그는 상세 본문을 읽는다. 접근이 막히면 사용자가 허용한 다른 출처를 사용한다. 네이버·티스토리·브런치·차이의놀이 유형은 실제 플랫폼과 일치시킨다.
- 현재 환경에서 사용 가능한 브라우저·커넥터·검색 API를 선택한다. 오래된 도구 이름이나 특정 API 키의 존재를 전제하지 않는다.

## 활동 작성과 검토

- 기본형 한 가지에 필요한 실제 재료를 `required`로, 추가 응용에만 쓰는 재료를 `optional`로 쓴다. 여러 출처에 등장하는 빈도로 필수 여부를 정하지 않는다.
- 수집 재료는 구체적인 한글로 기록한다. 액체풀/고체풀, 종이접시/평평한 종이, 폼폼/스펀지, 물감/색연필의 차이를 보존한다. 수량·크기·보호자 준비와 설치 환경은 단계에 남긴다. `substitutes`는 항상 `[]`다.
- 보호자가 준비할 일과 아이가 할 일을 구분한다. 원문에 없는 재료 변경·규칙·단순화는 `meta.activityReviews`와 `tip`에 편집 응용이라고 기록한다. 원문의 핵심 활동을 유지하는 응용은 출처를 보존할 수 있다. 다른 원리의 수동 놀이로 재작성했으면 `manual`로 표기하고 참고 원문을 메타데이터에 보존한다.
- 같은 재료를 쓴다는 이유로 중복 처리하지 않는다. 목표, 규칙, 핵심 동작, 결과를 비교한다. 이름만 바꾼 같은 활동은 중복이며 실제 다른 규칙이 있으면 차이를 기록한다.
- 안전·제품 사용 연령·입 탐색·작은 부품·도구 감독을 검토한다. 생밀가루·생반죽 직접 놀이는 게시하지 않는다. 작은 구슬·비즈·폼폼·워터비즈·플레이콘·일반 슬라임은 3세 미만 추천에서 제외한다. 풍선은 보호자가 준비하고 불지 않은 풍선·터진 조각을 즉시 수거한다.
- `educationalEffects`는 활동에서 해 보는 행동·관찰·상호작용으로 쓴다. 근거 없는 두뇌 활성화, 치료, 지능·집중력 향상 보장은 옮기지 않는다.
- `durationMin/Max`는 실제 놀이 시간, `prepTime`은 보호자 준비 시간이다. 원문 수치가 없으면 추정임을 메타데이터에 기록한다. 건조 대기시간은 따로 안내하고 단계 수만으로 시간·난이도를 자동 결정하지 않는다.
- `difficulty`는 아이에게 필요한 조작과 규칙의 복잡도로 1/2/3을 선택한다. `place`는 기본형의 환경으로 `indoor`/`outdoor`/`any`를 선택한다.

## 저장 구조

현재 앱 필드 기준은 `src/types/play.ts`다. `activities`에는 ID 없이 아래 필드를 쓴다.

```json
{
  "meta": {
    "query": {
      "originalRequest": "42개월, 해외 인스타에서 소근육 놀이",
      "requestedAgeMonths": 42,
      "ageMin": 36,
      "ageMax": 48,
      "ageRangeBasis": "42개월을 기준으로 주변 월령의 소근육 활동을 탐색하는 편집상 수집 범위. 개별 놀이의 대상 월령은 실제 동작과 원문을 별도 검토.",
      "requestedMaterials": [],
      "materialConstraint": "prefer",
      "areas": ["fine_motor"],
      "platform": "instagram",
      "region": "overseas"
    },
    "generated_at": "2026-10-09T15:00:00+09:00",
    "total_count": 1,
    "sources": { "instagram": 1 },
    "activityReviews": []
  },
  "activities": [
    {
      "name": "놀이명",
      "ageMin": 36,
      "ageMax": 48,
      "place": "indoor",
      "durationMin": 5,
      "durationMax": 15,
      "prepTime": 5,
      "difficulty": 1,
      "devAreas": ["fine_motor"],
      "materials": { "required": ["구체적인 한글 재료"], "optional": [], "substitutes": [] },
      "steps": ["보호자 준비", "아이의 진행"],
      "tip": "편집 응용 또는 놀이 팁",
      "safetyNotes": ["활동에 맞는 주의사항"],
      "educationalEffects": ["놀이에서 해 보는 행동"],
      "tags": ["활동 특징"],
      "source": { "type": "instagram", "url": "https://www.instagram.com/reel/확인한코드/", "instagramAccount": "확인한계정" },
      "status": "draft"
    }
  ]
}
```

- `tip`은 문자열 또는 생략이며 `null`을 쓰지 않는다. 태그에 연령은 넣지 않는다.
- `meta.activityReviews`는 활동명/후보 ID, 원문 재료·연령, 캡션/시각 확인 여부와 확인일, 편집 변경, 기존 놀이와의 차이, 시간·연령 추정 근거를 기록한다. 이 검토 메타데이터를 앱 놀이 객체 안에 복사하지 않는다.
- 수집본과 신규 병합본은 `draft`다. 재료·내용·출처가 정리되어도 사용자 검수 승인 전에는 `live`로 전환하지 않는다. 원문 미확인·필수 조건 미해결 활동은 보류 사유를 남긴다.
- 저장 경로는 `results/{월령또는범위}_{주제}_{timestamp}.json`이다. 후보 파일이 지정되었으면 원본을 보존하고 파이프라인용 수집 파일을 따로 작성한다.
- 다음 단계는 [normalize-materials](../normalize-materials/SKILL.md), 초안 병합은 [import-plays](../import-plays/SKILL.md)다. 기본 수집 요청에는 이 단계와 서버 검수 준비까지 이어 진행한다. 방금 생성한 정규화 파일을 명시해 임포트하며, 관계없는 미처리 파일까지 함께 병합하지 않는다.
- 실제 신규 ID를 [generate-play-images](../generate-play-images/SKILL.md)와 [이미지 생성 절차](../../../tools/local-review/IMAGE-WORKFLOW.md)에 넘깁니다. 별도 요청 없이 프롬프트 작성·실제 `image_gen` 호출·시각 확인·`review:image` 저장까지 수행합니다. `review:images`에서 모든 ID가 `ready`인지 확인하고 **그다음** 검수 배치를 만듭니다. 생성 실패 시 초안과 완료 이미지를 보존하고 미완료 ID를 보고하며 이미지 없는 새 배치를 만들지 않습니다.
- 놀이 이미지 준비 뒤 [generate-material-images](../generate-material-images/SKILL.md)를 이어서 수행한다. `review:material-images --ids <이번-ID목록>`으로 실제 사용한 미승인 재료를 중복 제거하고 실제 기존 이미지는 재사용한다. 이미지가 없으면 별도 요청 없이 실제 `image_gen` 호출·시각 확인·`review:material-image` 저장·매핑까지 수행한다. 새 재료가 모두 `ready` 또는 `existing`이 된 뒤 검수 배치를 등록한다. 재료 이미지 제작은 사용자 승인이 아니며 실패 시 새 배치를 먼저 만들지 않는다.
- 실제 신규 ID와 메타데이터를 보존한 **정규화 파일의 현재 경로**로 `pnpm review:prepare --ids <실제-신규-ID목록> --source <정규화-파일> --title <수집-제목>`을 실행한다. 원본이 `_done.json`으로 바뀌어도 존재하는 정규화 파일을 사용한다. 반환된 `batchPath`, `batchId`, `review`를 기록하고 후속 수정에는 같은 `--batch`를 사용한다. 신규 항목이 없으면 빈 배치를 만들지 않고 기존 해당 배치나 전체 현황을 안내한다.
- 놀이 이미지는 기존 색연필·수채화와 크림색 배경, 재료 이미지는 기존 흰 배경의 부드러운 3D 스타일을 유지한다. 해당 놀이의 실제 재료·행동과 월령에 맞추며, 놀이·새 재료 이미지가 미완료면 새 배치 등록 전에 생성 작업을 재개한다.
- `pnpm review:local` 서버가 이 저장소에서 실행 중이면 재사용하고, 없으면 저장소 루트에서 실행한다. 공통 절차대로 실제 API의 배치·내용과 검수 URL 응답을 확인해 **수집 건별 검수 링크와 전체 현황 링크**를 전달한다. 파일을 수정한 뒤에는 최신 파일로 새로고침한다. 서버 연결이 불가능하면 확인한 정적 HTML과 미연결 사유를 안내하며, `file://`에서는 서버 자동 저장·즉시 반영이 되지 않음을 구분한다.
- 검수 요청에는 기준 월령과 실제 수집 범위·선택 조건, 실제 신규 ID·놀이 수·신규 재료 수, 미완료 이미지와 보류 사유를 간단히 안내한다. 신규 재료는 화면에서 먼저 결정하고, 현재 본문·재료·이미지를 확인한 놀이만 사용자가 승인한다. 검수 준비 중 확인란·승인 버튼을 대신 조작하거나 승인 JSON을 만들지 않는다. 사용자 승인이 이미 명시된 경우에는 그 범위와 현재 해시를 기존 도구로 검증해 처리한다.
- 서버 화면의 승인 버튼이 해당 놀이를 검증·반영하므로 승인 후 JSON 내보내기나 별도 CLI 실행을 반복 요구하지 않는다. 서버의 `state.json`·거래 기록·영수증을 직접 편집하지 않으며, `file://`/JSON 방식은 공통 절차의 대안으로 유지한다. 별도 배포 요청 없이 배포하지 않는다.
