# 수집 후 놀이·새 재료 이미지 생성

전체 수집·임포트 요청에는 놀이 대표 이미지와 이미지가 없는 새 재료의 이미지 생성이 포함된다. 별도의 이미지 생성 요청을
기다리지 않고 **정규화 → draft 병합·실제 ID 부여 → 이미지 생성·저장 → 새 검수 배치
등록 → 서버 링크 전달**까지 진행한다. 조사만·정규화만·프롬프트만 요청한 경우에는
지정 범위에서 마친다. 승인과 공개 배포는 이 준비 단계에 포함되지 않는다.

## 생성과 저장

1. 이번에 임포트한 실제 ID만 기록한다. 신규 ID가 없으면 기존 이미지나 보류 항목을
   일괄 재생성하지 않는다. 중단 후 재개할 때는 기존 ID·정규화 파일을 재사용한다.
2. `pnpm review:images --ids <이번-ID목록>`으로 현재 내용 해시와 이미지 준비 상태를
   확인한다. `ready`는 현재 내용·파일과 생성 기록이 일치하므로 재사용한다.
   `missing`은 생성 대상, `stale`은 내용 또는 이미지 변경, `untracked`는 생성 기록 없는
   기존 이미지다. 기존 그림을 임의로 덮어쓰지 않고 이 수집 작업의 생성 결과인지 확인한다.
3. [generate-play-images](../../.claude/skills/generate-play-images/SKILL.md)의 베이스
   프롬프트·스타일 그림을 읽고, 실제 본문·재료·월령에 맞는 프롬프트를 ID별로
   `generated/play-image-prompts/<ID>.txt`에 저장한다. 기존 그림이 있다는 이유만으로
   새 프롬프트와 연결하거나 생성 기록을 직접 만들지 않는다.
4. 현재 환경의 실제 이미지 생성 도구(`image_gen`)를 **놀이별 한 번씩** 호출한다.
   정사각형 1024px, 기존 색연필·수채화/크림 배경, 글자·로고 없는 대표 이미지를 만든다.
   스타일 그림을 먼저 시각 확인하고 도구가 지원하는 참조 방식으로 제공한다. 핵심
   동작·재료와 월령이 보이는 장면 하나를 선택한다. 여러 놀이를 한 이미지/콜라주로 만들지 않는다.
   프롬프트 파일 작성만으로 생성 완료라고 보고하지 않는다.
5. 도구가 반환한 실제 결과를 시각 확인한다. 핵심 동작, 손·재료 연결, 사물 수,
   안전한 설치와 스타일이 맞지 않으면 수정한다. 이 검사는 제작 확인이며 사용자의
   이미지 승인과는 별개다. 프로젝트에 저장할 수 있는 생성 파일의 실제 경로를 사용한다.
6. 생성 전 계획의 `contentHash`와 사용한 프롬프트로 저장한다.

   ```bash
   pnpm review:image --id play_218 --file /실제/생성결과.png --content-hash <계획의-contentHash> --prompt generated/play-image-prompts/play_218.txt
   ```

   명령은 실제 이미지를 디코딩하고 정사각형·최소 512px를 확인해
   `images/plays/<ID>.jpeg`로 저장한다. `results/image-generation/<ID>.json`에는
   내용·이미지·프롬프트 해시를 기록한다. 등록 상태·사용자 검수 기록·앱 매핑은 바꾸지 않는다.
   생성 중 내용이 바뀌었으면 저장을 거절하므로 최신 내용을 읽고 다시 생성한다.
   요청받은 초안 이미지의 교체에는 `--replace`를 사용하며 이전 파일은 자동 백업한다.
   등록 완료·보관 항목에는 이 명령으로 덮어쓸 수 없다.
7. 아래 **새 재료 이미지** 단계도 수행한다. 놀이의 모든 ID가 `ready`, 새 재료가
   모두 `ready` 또는 `existing`인지 확인하고 **그다음** 새 배치를 만든다.

   ```bash
   pnpm review:images --ids play_218,play_219
   pnpm review:material-images --ids play_218,play_219
   pnpm review:prepare --ids play_218,play_219 --source results/normalized/이번수집_normalized.json --title "이번 놀이 수집"
   ```

   `review:prepare`는 새 배치의 모든 대표 이미지와 생성 기록이 현재 내용에 맞고,
   실제 사용한 미승인 새 재료 이미지도 모두 준비·연결되어야
   배치·검수 HTML을 작성한다. 하나라도 미완료면 수집 건별 검수 목록에 부분 배치를
   만들지 않는다. 병합한 초안은 놀이 라이브러리에 남으며, 완료한 이미지와 프롬프트를
   보존해 실패한 항목만 이어서 처리한다. 이미 게시한 배치를 `--batch`로 갱신하는
   작업은 기존 동작을 유지하므로 누락 이미지도 열어 확인·복구할 수 있다.
8. [서버 인계 절차](README.md#수집-스킬에서-검수로-넘기기)에 따라 API의 실제 ID·이미지
   해시·URL을 확인하고 링크를 전달한다. 사용자에게는 이미지가 포함된 검수 화면이 제공된다.

## 새 재료 이미지

놀이 이미지가 준비되면 [generate-material-images](../../.claude/skills/generate-material-images/SKILL.md)를
이어서 수행한다. `review:material-images --ids <이번-ID목록>`은 해당 놀이의 필수·선택
재료 중 `reviewPending`인 slug만 중복 제거한다. 여러 놀이가 같은 새 재료를 쓰면 한 장만 만든다.

- `existing`: 실제 기존 JPEG와 매핑이 있어 그대로 재사용한다. 브랜드 기본 이미지는
  실제 재료 이미지로 인정하지 않는다. `ready`: 현재 재료 정의·이미지와 생성 기록이 일치한다.
- `missing`: 스킬의 흰 배경·부드러운 3D 스타일로 실제 `image_gen`을 호출한다.
  원문·정규화 파일의 재료 형태·용도를 확인하고 `generated/material-image-prompts/<slug>.txt`에
  사용한 프롬프트를 남긴다. 놀이 그림과 다른 재료 아이콘 스타일을 적용한다.
- `unlinked`: 실제 기존 파일은 있으므로 생성하지 않고 연결만 한다.
  `pnpm review:material-image --slug <slug> --definition-hash <계획의해시> --link`를 사용한다.
- `stale`: 정의 또는 파일이 바뀐 상태다. 최신 재료 의미를 확인해 이 작업에서 변경한
  미승인 재료만 다시 생성한다. 기존 승인·보류 재료를 일괄 교체하지 않는다.

생성 결과의 재료 형태·용도·스타일을 시각 확인하고 저장한다.

```bash
pnpm review:material-image --slug new_cup --file /실제/재료생성결과.png --definition-hash <계획의-definitionHash> --prompt generated/material-image-prompts/new_cup.txt
```

명령은 정사각형·최소 512px·디코딩을 검증하고 `images/material/<slug>.jpeg`에 저장하며
`src/constants/materialImageSources.ts`의 해당 slug만 연결한다. 생성 기록은
`results/image-generation/materials/<slug>.json`이다. 정의·이미지·매핑의 동시 변경을
감지하고, 요청받은 교체의 `--replace`는 기존 canonical 파일을 백업한다. `--link`는 실제
파일만 연결하며 생성 기록을 꾸며 만들지 않는다. 실제 생성 없이 파일을 새 생성물로 기록하지 않는다.

`reviewPending`·사용자 의견·결정·놀이 상태는 그대로 유지된다. 이미지 연결은 검수용
준비이며 재료 등록 승인이 아니다. 재료 라이브러리와 해당 수집 건의 **재료 검수** 탭에
실제 이미지가 표시되고, 사용자가 이미지·용도·형태를 확인해 신규 추가·대체·보류를 결정한다.
새 배치에는 재료 이미지 해시도 검수 대상에 포함되므로 이미지가 바뀌면 이전 확인은 무효다.
이미지가 사라진 새 배치의 재료는 신규 추가할 수 없으며, 대체·보류는 그대로 사용할 수 있다.

## 중단과 수정

- 이미지 도구 실패·한도·사용 불가 때는 초안·프롬프트·완료한 결과를 보존하고 미완료
  ID와 원인을 보고한다. 새 배치를 만들거나 이미지 없는 상태를 검수 준비 완료로
  보고하지 않는다. 원본 썸네일·기본 이미지·다른 놀이 그림으로 대신 채우지 않는다.
  별도 API 키·유료 API 경로로의 전환은 해당 도구 지침과 사용자의 허용 범위를 따른다.
- 신규 재료의 의미·임시 정의가 정리된 뒤 생성한다. 새 재료 이미지 생성은 사용자 승인
  전에 수행하며, 재료 검수 결정은 사용자에게 맡긴다. 생성 실패 시 새 배치를 먼저 만들지 않는다.
- 기존 검수 의견에 따라 본문·재료·핵심 동작이 바뀌면 영향을 받는 **수정 요청 초안만**
  최신 내용으로 다시 생성·저장하고 같은 배치를 `review:prepare --batch ...`로 갱신한다.
  승인·보류·등록 완료 항목을 일괄 재생성하지 않는다. 내용 또는 이미지 변경 시 기존
  확인값은 무효가 되며 사용자가 새 화면에서 재검수한다.
- `ready`는 이미지 제작 준비 상태다. `status: draft`, `imageStatus: review`는 사용자
  승인까지 유지한다. 생성 기록이나 사용자 확인란·승인·서버 상태를 직접 꾸며 쓰지 않는다.

이 흐름의 자동 실행 주체는 수집 스킬을 수행하는 Codex다. 로컬 HTTP 서버는 생성 도구를
호출하는 대신 완성된 배치와 이미지를 읽어 제공하며, 사용자 승인만 기존 검증 도구로 반영한다.
